Equal-output-length full-model comparison

The user requested six fresh server sessions on the same eight H100s: LongBench and NuminaMath, one sixteen-request group each, with native EPLB OFF, native EPLB ON and our unchanged resident method. Prompts, arrival calendars, rates, model/checkpoint, hardware and placement policies remain those of the completed natural-stopping experiment. These are new executions of previously used payloads and calendars, not a fresh generalization sample.

Why were the previous outputs shorter?

Verified: all previous measured requests completed, and paired prompts and generation settings matched. NuminaMath used the same 2,048-token cap and temperature zero in every arm. Our method ended naturally on 14/16 requests and reached the cap on two; OFF ended naturally on 11/16 and reached it on five. Our answers were shorter for nine paired prompts, longer for three, and equal length for four. Thus the method is not uniformly shortening answers. Private output hashes match the public records, so this is not missing client output or dropped requests.

Native ON also diverged from OFF: only one of sixteen NuminaMath answer hashes matched, and their total output counts were 16,457 versus 17,519. Our total was 15,642. Existing NuminaMath warmup diagnostics show identical first tokens in all eight OFF/custom pairs, followed by token-path divergence after shared prefixes averaging 236 tokens. Selected-token log probabilities differ even on the shared prefix (mean absolute difference about 0.0059); this is diagnostic evidence of numerical differences, not a full-logit or answer-quality test. All natural-stop warmup diagnostics ended in a model EOS token. Measured requests did not return token IDs, so their exact final EOS IDs are not directly observed.

Plausible mechanism, not isolated cause: changed expert placement, physical dispatch, kernel/batch shapes and floating-point reduction order can alter greedy token choices; autoregressive decoding then follows a different answer and stopping point. Temperature zero does not imply bitwise identical results across these configurations. The records do not identify which operation first caused divergence, nor rule out every full-model numerical issue. Prior weight/representative arithmetic checks remain necessary evidence but do not certify all logits or semantic quality.

Bound output/termination audit and four shared-prefix diagnostic reports preserve the numerical observations without publishing private prompts, answer text or token arrays.

The length targets are copied from the prior completed natural-EOS OFF records, without selecting by speed. Each request sends max_tokens=N, min_tokens=N, ignore_eos=true, and empty explicit stop lists. The pinned vLLM implementation retains model EOS IDs for minimum-length masking, suppresses stop-token logits until the target, and terminates at the length bound. All methods pay the same minimum-length processing overhead. Every request must return exactly its frozen target with length termination; both the primary report and the independent arithmetic checker reject missing, short or mismatched outputs.

Each fresh server performs the same two eight-request pilot warmups. Both passes use the previous OFF warmup00 output lengths; the first collects diagnostics and the second uses ordinary response payloads. Measured requests use their separate OFF reference lengths. All warmup and measured targets and source-record hashes are frozen in the protocol. The runtime archives these public references alongside the logs. The first reserved group and the exact original arrival calendar are retained.

Arm order reverses the prior experiment before any new execution: LongBench ON → OFF → resident, NuminaMath resident → ON → OFF. There are six sessions, 96 measured requests and 96 warmup executions. Native configurations and the resident algorithm are unchanged. Source inspection for the exact sampling behavior is archived in the pinned-source audit.

What a favorable result would mean

The primary comparison is resident/OFF; resident/ON is secondary. Report mean/p95 response, TTFT, completed elapsed including horizon and drain, native prefill/decode phases, cache/preemption counts and output lengths separately for each workload. Keep the existing descriptive 5% useful-gain and 2% regression margins. A reduction here cannot be attributed merely to fewer generated tokens. It still does not hold token identities, expert-routing distributions, dynamic batch shapes or answer quality identical. Forced continuation changes natural answer semantics and is a performance control, not a quality benchmark.

One group per workload means descriptive ratios only: no confidence intervals, request bootstrap, significance test, pooled overall effect or reproducibility claim. Actual prefill/decode dominance must be measured again. Native async launch or HTTP drain is not proof of committed weights or migration payback. Preserve the earlier negative results and the natural-stopping comparison; do not replace them with this control.

The six-session experiment completed and passed these checks. Read the equal-output results and limitations: no observed mean-response speedup over OFF; a preliminary matched-length gain over ON on NuminaMath.
