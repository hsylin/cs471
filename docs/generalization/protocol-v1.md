# Generalization capture and pilot protocol

This protocol is frozen before new GPU capture or performance timing. It governs source selection and the pilot. A separate final manifest must resolve pilot-dependent sample size, exact schedules, execution hashes and analysis before final timings; this document alone does not assert that final measurements have been frozen or completed.

We test incremental combined/shortcut layer-job response latency. Earlier experiment commit71a1baa remains unchanged. The three arms preserve native SKIP, logical expert IDs, combining weights and the fixed initial physical map `[0,...,127,0,...,31]` (80slots/rank). The map is content-independent and will remain unchanged; there is no per-test-set placement optimization. The replica budget is32. The exact pinned checkpoint is Qwen/Qwen3-30B-A3B revisionad44e777bcd18fa416d9da3bd8f70d33ebb85d39, layer0 BF16 H2048/I768/E128/top8. Runtime is the existing pinned vLLM source and replicated inputs/output all-reduce. Only reservation4872248 on kh014 and its previously recorded H100 UUIDs are permitted.

The public content manifest fixes30 groups of64 documents: two pilot groups and eight final groups per WildChat, MBPP and GSM8K. Selection uses seed471501, source IDs and normalized-text hashes after global exact/near-duplicate filtering (five-token shingles, Jaccard≥0.8). WildChat's sampling frame is the first8,192 rows of the first shard of its pinned filtered release; only non-toxic English nonempty first-user turns qualify. MBPP uses task descriptions from the full pinned release, without solutions/tests; GSM8K uses test questions without answers. Original dataset split labels are retained. No assertion of absence from checkpoint training is made.

We tokenize plain text with the pinned checkpoint tokenizer, no added special tokens or chat template. At least eight tokens are required; capture retains the first512 tokens. Every prompt has separate causal attention, beginning at position0; prompts are not concatenated for attention. No answers are generated or teacher-forced. The capture executes native checkpoint embedding, layer0 attention, residual, normalization and router, then records inputs before experts. Exact boundary, router, formula and BF16 round-trip checks must pass. Source text remains in the local preparation directory; public manifests contain identifiers and hashes. Near duplicates and rejected eligibility records are archived, never silently reused to fill a block.

B128 is the main shape, chosen before any new routing/performance observation. Some MBPP groups have fewer than1,024 unique tokens, so requiring B1024 would force within-job token repetition or altered content grouping. We spend the bounded design on content and arrival variation. Larger-batch results, if later added, must be labeled optional diagnostics. Layer jobs will select only authentic captured records; every reuse, prompt origin and token position must remain reconstructible. A long deterministic traversal with cycle-specific permutations replaces the prior32-job repeating sequence. It remains a constructed layer workload, not a replay of complete user requests. Length matching and old-sequence/control-alignment sensitivity are diagnostics.

Azure2024 code/conversation source assets and release digests must be verified. Pilot uses the earliest two available source dates; final uses later source dates only. Nonoverlapping contiguous256-arrival blocks, their next boundary timestamp, original row indices and request-length metadata are retained. Selection is hash-ranked within date, never by burstiness or favorable performance. Content groups are paired with arrival blocks before timing. Timestamp ties are preserved; original precision and any source-date/documentation discrepancy are recorded. If insufficient dates exist, the final allocation must explicitly shrink; synthetic data cannot silently replace external traces.

Every source timestamp maps to one preassembled B128 layer job; original request lengths are not executed. Per-content native saturated calibration defines the nominal0.85load schedule. A second schedule uses a single absolute arrival rate computed from the geometric mean of pilot native capacities at load0.85, shared across all content and treatment arms. Both scale original offsets by one exact rational factor, with integer-nanosecond rounding, rather than resampling gaps. Raw offsets and scaling remain archived. Preserve absolute releases under overload and finish every admitted job. Setup/materialization/warm-up/reference checks are excluded and recorded; online selection, command/ACK, synchronization, native proposals, equality/rank agreement, completion and drain are included.

The provisional budget is72 pilot treatment trials (six content groups×two arrival types×two rate definitions×three arms), up to288 final treatment trials (24groups×two types×two rates×three arms), and24 diagnostic trials. Native-only calibrations are counted separately. No technical repetitions enlarge independent sample counts. Use all six arm permutations in balanced blocks. All treatment arms receive identical conditioning and exact input order. No profiler runs concurrently with primary timing.

Pilot-dependent allocation may choose six or eight final content groups per dataset. The planning rule uses dispersion only: pool the pilot content-group paired log-response effects after averaging nested arrival/rate cells, estimate projected95% half-width using2.571×s/sqrt(3n), and choose n=6 only if this is≤0.03; otherwise choose n=8. Also report each dataset's pilot dispersion. This is a small-pilot planning heuristic, not a power guarantee; apparent mean benefit cannot change sample size or select datasets. The final day/block matching and multiplicity analysis must be frozen in executable code before measurement. A fallback is not included unless a reproducible pilot failure is diagnosed; adding one requires a pre-final amendment and a reduced matrix, never deleting the existing combined control.

The primary estimand is the equal-dataset/equal-block geometric paired combined/shortcut mean-response ratio at native-calibrated0.85load. The two-sided95% upper bound must be<0.95. Seven guards use Bonferroni one-sided confidence1−0.05/7 and upper≤1.02: each of three datasets' mean response under each of two rate definitions, plus aggregate native-calibrated finite-trial p95response. Report per-dataset/arrival-type estimates even when inconclusive. The common-absolute-rate contrast cannot be replaced by normalized load. Combined/native is a hierarchical secondary comparison only after primary+all guards pass. Shortcut/native and mechanism associations are descriptive.

The analysis must retain content/day dependence, resampling whole paired content/time bundles and clustering content groups that share an arrival date. We have one public time span and constructed document groups, not a random sample of production deployments. Individual jobs and repeated records are not independent uncertainty units. A256-job p95 is a finite-trace statistic, not a precise population-tail estimate. No claim of independent GPU replication follows from same-team CPU audits.

The hypothesis fails its useful-gain test if the primary upper bound reaches0.95, and is unsupported on a guarded workload if that guard exceeds1.02; an inconclusive guard is not proof of harm. A lower bound above1.02 on a workload is positive evidence of unacceptable regression. Any violation of logical routing, combining weights, token conservation, atol0.02/rtol0.03 numerical checks, rank agreement, fixed resident weights/map or normal completion invalidates the performance claim. Fewer tiles/bytes or lower service without measured response benefit does not rescue failure. Publish every completed case and failure reason, source/code manifests and independent arithmetic/state audits.
