# Floating-weight provenance correction

This amendment supersedes the diagnostic v1 combining-weight hash and marks all24 v1 diagnostic trials ineligible for the requested provenance-validated comparison. Their raw records, derived summary and failing independent audit remain archived. The unchanged main216-trial experiment is unaffected. No latency result is used to select this correction or change the diagnostic design.

The v1 diagnostic runner called `optimization.common.array_hash` for the executed combining weights. That shared helper converts its argument to int64. Combining weights strictly between zero and one therefore become zeros before hashing, so the recorded digest cannot distinguish their values. Numerical preflight and other checks do not substitute for the missing weight identity. The v1 evidence is not waived into eligibility.

Revision2 hashes the actual executed GPU combining-weight values after the measured interval. The selected tensor has shape `[256,128,8]` and is copied to CPU, converted explicitly to little-endian float32 in C order, checked finite, and hashed with SHA256 over its bytes without a header. The field `executed_combining_weights_encoding` is exactly `little-endian float32; C-order; no header`; `instrumentation_revision` is2. The implementation uses `np.ascontiguousarray(values,dtype='<f4').tobytes(order='C')`, rather than the integer-array helper. Shape and executed raw-index sequence remain explicit in the records. The independent verifier reconstructs these exact bytes from the authenticated source bank, captured-record indices and executed sequence.

A CPU mutation test distinguishes two valid arrays whose values are all below one and whose integer-cast representations collide. It also checks equivalence under Fortran layout and big-endian float32 input, plus rejection of nonfinite values. The analyzer requires the explicit revision and encoding, valid digest syntax and identical weight identities among paired treatments on the same sequence. Independent reconstruction remains necessary; syntax and pairwise equality alone are not authentication.

The v2 frozen plan uses the identical three pilot states, source calendars, eight-condition orders, job sequences, fixed map, algorithms, conditioning and timing paths from v1. Only post-timing weight provenance and its validation change. The24 trials are rerun under the new separate diagnostic source hash. Together,72 main-pilot,216 main-final,24 invalid-v1 diagnostic and24 corrected-v2 diagnostic executions total336, below the384-treatment budget. Native-only calibrations are counted separately. No original main source, algorithm, endpoint or final result is modified.
