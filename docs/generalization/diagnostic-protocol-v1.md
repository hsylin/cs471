# Bounded generalization diagnostics

These24 trials are descriptive development diagnostics, separate from the frozen main pilot/final analyses. They use the same two reserved H100s, Qwen layer, B128, fixed map and32 extra replicas. No algorithm, parameter, main endpoint or main source-identity file changes. Results cannot select a treatment, change the primary sample size, replace a final case or alter the main acceptance rule.

One of the two pilot content groups per GSM8K, MBPP and WildChat is selected by the smallest canonical-JSON SHA256 of `[471520,"select",dataset,group_id]`. Selection reads only identifiers. Each selected state uses its existing pilot-v2 code trace block and native-calibrated0.85load calendar, byte-identical to the main pilot manifest. No final content, final timing or outcomes enter selection. These are three development states, not a representative sample of all workloads.

Each state executes eight conditions once: shortcut and combined on the main256-job sequence; shortcut and combined on a32-job cycle at phase0; shortcut and combined on that same cycle at phase16; precomputed-native and precomputed-online assignments on the main sequence, both with the shortcut. Thus3 states×8 conditions=24 trials. The main-subset runs intentionally repeat some main-pilot conditions; they do not add independent content units. No native-only diagnostic arm is added because the incremental control is shortcut and native is already in the main study.

The main sequence uses raw jobs16–271. Both cycles use only raw jobs16–47, each eight times. Their measured index at step i is `16+((i+phase) mod32)`, with phase0 or16. Every job in the cycle has the same frequency in both phases. The phases change which inputs fall within the16-call observation windows ending at steps63,127,191 and255. Main-versus-cycle changes both repetition and input coverage; it does not isolate a pure cache effect. Phase0-versus16 retains the same input multiset but changes its order relative to arrivals and native boundaries, so it is sensitivity evidence, not exclusive attribution to the controller.

The four adjacent comparison pairs are main, cycle0, cycle16 and offline. A seeded random base pair order is rotated across the three dataset states. Pair direction alternates by dataset index plus fixed pair index, yielding the closest possible2:1 precedence balance with three states. State order is separately shuffled with seed471521. Exact eight-condition orders, positions and pair precedence counts are frozen and reported. There are no technical repeats, confidence intervals, p-values or diagnostic acceptance gates.

The offline conditions precompute the exact physical assignments produced by the frozen native and frozen online algorithms for every one of272 inputs. Their hashes must match the already GPU-verified mapping outputs in main input preparation. A common precomputed adapter copies physical IDs and records native physical load counts on the GPU; its allocation, pointer lookup, copy/record kernel, synchronization and all other runtime work remain charged. Both adapters are checked on every input against the exact assignments and physical counters before timing. Their construction and checks occur outside timing and their elapsed preparation is recorded.

Precomputed-online/precomputed-native compares assignments through the same adapter. It is an optimistic mechanism comparison for known assignments. Precomputed-online is a zero-selection-cost replay of this particular frozen algorithm, not a globally optimal assignment or mathematical runtime bound. Comparing charged combined against precomputed-online also changes the route execution adapter, so the difference is a total route-path effect and cannot be labeled exclusive GPU selector time. All real online selection remains charged in combined. No precomputed result is a deployable policy claim.

All conditions retain the frozen64-step full-path conditioning cycle, native SKIP observation/planning, shortcut rank agreement, same absolute calendars and FCFS command/ACK coordinator, terminal suppression and complete drain. Raw arrivals, admission, start, completion and per-rank envelopes are saved. Physical/logical windows, fixed map/weights, no migration, all272-input preflight, source/reference numerical checks and normal completion must pass. Per-sequence identities are retained; trajectories may differ between sequences but must agree between paired treatments on the same sequence. A diagnostic invalidity is reported; no case is silently replaced.

The report contains paired mean/p95 response, service, queue, completed elapsed, drain, throughput, boundary-associated service and ordinary-step service, plus active-copy/tile counts. These are descriptive metrics and associations, not independent kernel attributions. Boundary-associated includes steps63,127,191,255; the terminal step has a distinct suppressed-proposal path and is reported separately. Captured-document length matching is omitted: it would alter the selected input construction and exceed this bounded subset. No claim of length matching or natural request replay is made.

The diagnostic plan references the unchanged pilot plan, its captures/calendars and original execution hash. A separate diagnostic source hash includes the new runner, plan, analysis, wrapper, freezer and this protocol in addition to all main execution pins. The diagnostic does not alter main runtime files or their source identity. Freeze precedes all diagnostic timing; run only after other GPU measurements are stopped.
