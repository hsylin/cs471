# Within-rate treatment-order amendment

This amendment corrects the treatment-order construction before any pilot or final treatment timing. Protocols v1 and v2 remain unchanged as historical specifications. All workload selection, inputs, fixed placement, budgets, timing boundaries, correctness checks, endpoints, sample planning and statistical rules from v2 remain in force. The correction changes case order assignment and the corresponding execution/analysis source hashes.

The first freezer assigned permutation index `(2*i+ri) mod6`, where i indexed a content/arrival-type assignment and ri selected the rate definition. Although this balanced all six permutations across the full matrix, calibrated-rate cases received only even-indexed permutations and common-rate cases only odd-indexed permutations. Thus position and precedence were not balanced within the rate conditions used by the primary endpoint and guards. Global balance alone was insufficient. No treatment results were inspected to identify or correct this design defect.

The replacement constructs each rate condition separately. For rate index ri in the fixed order `calibrated, common`, start from the canonical case-key order, shuffle the keys with a local Python `random.Random(order_seed+ri)`, and assign the six permutations of `[native,shortcut,combined]` cyclically to the shuffled cases. Case keys identify the content group and its assigned arrival type/block; the exact ordering and assigned permutations are stored in the frozen manifest. Rate definitions, source blocks and jobs are unchanged. Later case execution ordering does not alter each case's frozen arm order.

There are12 pilot cases per rate, so each permutation occurs twice within each rate. With six final content groups per dataset there are36 cases per rate and six occurrences per permutation; with eight groups there are48 and eight occurrences. Consequently each arm appears equally often in all three positions, and every pair's precedence is balanced, within each rate condition. This balance does not make observations independent or eliminate all temporal drift; actual order and per-rate position counts are archived.

The analyzer requires exact six-permutation balance both globally and separately within `calibrated` and `common`. It also checks each recorded triplet's actual arm order against the frozen case. A globally balanced plan that assigns only three permutations to each rate is rejected. Mutation tests cover that specific failure.

The six native-only calibrations completed under the earlier source identity are retained as superseded preparation records. They are not selected for treatment comparisons or used to choose a better-performing design. Native calibration will be rerun under the new frozen source identity so calibration and treatment share a consistent implementation. The unexecuted pilot-v1 treatment plan is superseded, and a new pilot plan pins this amendment, its rate-balanced assignments and the updated source/analysis hashes. No previously completed experimental study is modified.

For reproducibility, the inference output adds `bootstrap.draw_indices_sha256` without changing any draw or statistic. Hash input is the byte concatenation of the three complete `(100000,n)` draw-index tables in dataset order `gsm8k,mbpp,wildchat`, each encoded as little-endian signed64-bit integers in C order, without a header. This is dataset-table concatenation, not interleaving columns across datasets.
