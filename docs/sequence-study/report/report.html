The fresh 192-trial experiment remains negative versus EPLB-off: the repaired dispatcher has 0.87% higher service time and 7.00% higher mean response at high load (response 95% CI +5.54% to +8.85%). What was controlled

Contiguous input traverses captured document prefixes in token order, repeats whole-bank cycles, and truncates to exactly 4,096 × 128 occurrences. Mixed input uses precisely the same occurrence bag with a seeded shuffle and deterministic duplicate-removing cross-batch swaps. No batch repeats a captured token. All arms and modes share common warmup and absolute arrivals. Short source banks repeat every roughly 15–43 batches: this does not create long-lived 1,000-step hotspots.

Mixed versus contiguous changes batch composition and temporal order together. A six-trial whole-batch shuffle subset preserves batch membership and changes only ordering. It is a limited diagnostic, not a second generalization study. Selection used identifiers and fixed seeds without consulting routing or timing. Original negative results remain archived.

What remains unresolved

Native-on can adjust only about twice in these 4,096-job runs, with native readiness deferrals retained. Launch-to-commit time overlaps execution, so it is not exclusive migration cost. Episode-level cumulative service differences are reported, but do not isolate migration-specific payback. Stable severe skew, longer operation, other layers, decode, dynamic batching and token all-to-all remain outside this experiment.

The same two reserved H100 94 GB GPUs execute one pinned Qwen3-30B-A3B layer 0, BF16/B128/top8. Off uses128 physical slots; resident/native-on use 160 under the maximum 32-replica allowance. This is replicated input plus native output all-reduce and eager execution. No universal EPLB-off superiority or end-to-end serving speedup is claimed.

In all 16 native-on trials in the two main supplemental input conditions, terminal cumulative service remained above the paired off run by 449–552 ms. This demonstrates no episode-level recovery of its total extra cost in these runs, not an isolated per-migration payback time. The longest single-document runs contain 101, 103, 512, or 512 tokens across the four bundles (at most four batches); a 1,000-step native observation window averages roughly 23–68 whole-bank cycles. Adjacent-job demand changes can therefore coexist with almost unchanged window-average demand.

Native-on retains a 1,000-step observation window and 3,000-step adjustment interval. The harness fixes the initial counter at 2,250, giving its first opportunity after zero-based job 749; native readiness may defer later opportunities. This controls the counter phase and is not untouched full-serving initialization.

Correctness and reproducibility

All prepared inputs receive full-output and logical routing checks; resident assignments are checked against the frozen CPU oracle. Rank agreement, checkpoint weights, committed maps, native sampling windows, sender bytes, normal completion, source/input hashes and raw-clock statistics are audited separately. Offline clean-checkout reconstruction is archived. These are same-team independent implementations, not external-laboratory replication.
