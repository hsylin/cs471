Sustained serving: 512 requests per dataset

Status: completed and audited. All 24 main sessions and both payback diagnostics finished. Earlier negative results and failed attempts are preserved.

The question is whether completed EPLB migrations repay their overhead over sustained full-model serving, and whether the fixed resident dispatcher improves response latency. One continuous group of 512 requests from each dataset is served by each method. The same eight H100s, pinned Qwen3-30B-A3B checkpoint, native vLLM activation backend and prior resident placement are retained.

Completed results

No practically useful end-to-end speedup over EPLB OFF. All 24 main sessions completed, totaling 12,288 successful measured requests. With exact output lengths, resident dispatch reduced mean response by only 0.78% on LongBench and 0.43% on NuminaMath, below the declared 5% useful-gain target. One group cannot establish repeatability or statistical significance.

B4 reduced matched NuminaMath mean response by 5.04% relative to B3, but remained 7.80% slower than OFF. Its matched LongBench improvement over B3 was 0.86%, while remaining 4.16% slower than OFF. This is an observed policy contrast, not proof that TV identifies higher-payback individual migrations; there is no equal-frequency cooldown control here. B1 versus B2 mixes replica capacity, placement and policy consequences.

Migration payback remains causally inconclusive

The target step 3750 existed on every rank. The allow branch changed 6,462 slots and completed all 48 layers; the skip branch and all other opportunities retained their maps. However, predecision demand hashes and candidates differed on all eight ranks; only 9/15 completed predecision outputs matched, and only 13/48 outputs matched overall. The old maps agreed, but the active KV state was not cloned. Allow accumulated 2.316 seconds more HTTP execution time. This cannot establish either a migration benefit or its causal repayment time.

The main policy-level cumulative response curves are included in the JSON. They charge online overhead but cannot separate the cost and benefit of an individual migration. The actionable conclusion is to keep OFF as the reference and treat resident dispatch as near parity on these matched-length workloads; larger sustained request counts did not produce the declared useful gain.

Preserved attempt and HTTP amendment

The first main OFF session completed511 of512 requests; one disconnected before HTTP headers. All records remain preserved. The server subsequently completed365 requests. A connection-reuse race is plausible but unproven. Attempt2 uses a fresh TCP connection for every request in every arm, with no request retries; connection setup remains charged. Pilots and main sessions use this common transport policy. A stale resident source-manifest hash was corrected before its launch; the healthy OFF pilot was retained without rerunning, and runtime code was byte-identical across that handoff. Measurements continue with unchanged data, arrivals, generation and model policies. The client tests verify separate connections and no retry of a disconnected POST. No valid speedup comparison is drawn from attempt1.

Inputs and stopping

Hash-based selection uses source IDs, duplicate/group checks and context fit. LongBench retains the prior Qasper, GovReport and HotpotQA tasks; NuminaMath retains the pinned candidate frame. There are eight disjoint pilot requests and 512 final requests per dataset. Some inputs overlap earlier experiments; this is not a wholly fresh-content generalization test.

Natural stopping uses normal EOS, temperature0, no thinking, and a common8192-token ceiling within32768 context. Full prompts are not truncated. LongBench prompt lengths span1910–23561 tokens and NuminaMath27–1436. Ceiling hits and actual native prefill/decode duration fractions must be reported. LongBench must not be called prefill-bound merely because of its name.

A single contiguous Azure code trace block supplies512 arrival timestamps plus a boundary timestamp, uniformly scaled to the prior per-dataset rates. The exact calendar is shared by methods. Content and arrival patterns come from independent sources, not a reconstructed joint production workload. The client preserves absolute arrivals, permits512 outstanding requests and drains every request.

Natural and matched-length comparisons

Twelve natural-stopping sessions are followed by twelve matched-length sessions: two datasets × six methods per stage. Each matched target is that request’s generated token count in the designated natural OFF reference. All targets are frozen before any matched server starts; every method is rerun regardless of the natural ranking. Fresh servers are used per dataset/arm, with the same two eight-request warmups. Warmup placement may affect measured results and is recorded.

Output counts, ceiling hits, full-response mean/p95, TTFT, native request phases, elapsed time, drain and throughput are separate metrics. Startup and warmup are reported separately from warmed serving. Equal lengths do not imply identical generated content, routing or quality. One group per method supports descriptive ratios only: no confidence intervals or significance claims. The useful-gain margin is5% versus OFF, with a2% regression guard.

Migration evidence and payback limits

Records cover proposals, admitted maps, transfer enqueues, received bytes, workspace-copy events and observed GPU completion. All-rank agreement is checked offline. Unenqueued and unobserved completion remains censored; asynchronous draining is not evidence of commit. Copy times across ranks are not additive wall time, and proposal-to-commit intervals include waiting.

The main comparison reports cumulative policy-level response savings against OFF, including online overhead. These curves are not isolated causal payback for a particular migration. Two additional matched-length B2 pilot replays use single-inflight execution, suppress earlier/later migrations, and differ in allowing/skipping the proposal at engine step3750. The analysis checks whether the opportunity exists, the candidate changes, predecision maps/demand agree, and completed prefix outputs match. Active-request KV state is not cloned; generated routes may diverge. Any failed comparability check makes migration-specific causal payback inconclusive. A negative or censored result is retained.
