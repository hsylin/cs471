# Resident-path fix: diagnostic and fresh-confirmation protocol

**Fresh-treatment protocol, finalized after development and before fresh treatment timing.** The archived diagnostic order/source plans preceded their respective development runs. The implementation choice below uses only those reused pilot inputs; it does not use fresh treatment outcomes. This protocol, selected implementation, source inventory and derived arrival plans are frozen before their corresponding calibration/treatment stages. Earlier source, raw records and conclusions remain immutable.

## Question and scope

Can one implementable change to the current resident method reduce completed layer-job response relative to genuine stock EPLB-off, while also improving the unchanged current method? The setting remains the same reserved two H100s, one Qwen3-30B-A3B MoE layer, BF16, B128, real stock gate/top-k, native expert kernels/output reduction and a maximum allowance of 32 additional expert replicas. This is eager replicated-input TP2+EP with FCFS layer jobs, not full-model or natural chat-request serving.

The preceding stock experiment found the current 160-slot method slower than stockoff 128 at both offered loads. Its hot-path service difference and periodic-control associations motivate diagnosis, not a predetermined causal explanation. Different resident geometry, routing decisions and controller work are confounded in the direct comparison. Reduced rank-level work counts alone cannot establish speedup.

## Identical-assignment development diagnostic

Use all six previously used stock pilot content groups, not fresh final data. For each group, retain the first 64 authenticated unique measured batches, then cycle them eight times: 512 jobs. This is constructed repeated-input diagnostic replay. The real gate/top-k executes in every variant. Record data identities, exact sequence and prior source overlap; jobs/cycles are not independent statistical units.

The five variants are stockoff as a contextual128-slot anchor, plus a 2×2 comparison on identical 160-slot fixed placement:

| Routing computation | Current recording/controller package | Recording/controller inactive |
|---|---|---|
| Current online selector | `current_online` | `static_online` |
| Exact precomputed current assignments | `current_offline` | `static_offline` |

Offline assignments reproduce the current selector's exact physical expert choices on each authenticated input. Offline construction is excluded and labeled; actual gate/top-k, the physical-map/output adapter, input handling, native experts and completion remain charged. This estimates removable package costs; it is not a strict runtime bound or an online serving competitor. Every online/offline pair must have identical logical IDs, combining weights, physical assignments, source map, expert weights and numerical output within the declared tolerance.

The control-free factor removes the recording/control subsystem as a package. It must preserve fixed residency, actual inference and outputs, and must show no observed-window advancement, proposal, transfer or map commit. Its contrast does not isolate only CPU planning or only periodic boundary cost. Report factorial differences and interactions, raw whole-episode service, and associations at the eight 64-step boundaries versus other positions; do not sum overlapping GPU kernels or label temporal associations exclusive component costs.

There are two technical repetitions per group/variant, 60 diagnostic runs total. Freeze one base permutation per group and execute its exact reverse for the second repetition; this gives exact within-group pairwise-precedence balance with near-balanced positions. Retain all runs. Use ordinary completed-job timing with current inference-stream completion and common CPU ACK; no device-wide synchronization may serialize background work inside a job. Setup, conditioning and separate profiler runs are excluded and identified. No CIs or p-values are assigned to this small reused-input diagnostic.

## Selecting one fix

The selected implementation must follow measured diagnostic evidence, not the desirability of a particular kernel or controller change. The selection record will state the mechanism targeted, changes relative to current, actual development measurements, correctness results, unmeasured alternatives and remaining limits. A proposed fused or static implementation is not automatically the chosen fix.

Only one chosen online implementation enters fresh confirmation. Charge its selector, input handling, runtime validation and control work normally; an offline oracle cannot become the final arm. Preserve logical top-k computation, exact fixed-map legal expert coverage and checkpoint weights. If it changes physical choices, record that explicitly rather than claiming a pure overhead reduction. Final data cannot tune the implementation, thresholds, content, arrival selection, ordering or sample size. Correctness failures require an explicit preserved amendment, not silent replacement. A development speed miss cannot be hidden by dropping development runs; the final selection record states it.

### Selected bounded repair and development evidence

The selected implementation is the controller-free, single-CTA fused dispatcher in `configs/resident-fix-selected-v1.json`. It preserves the current method’s exact greedy physical assignments and native logical gate/top-k. The native enabled layout constructs 160 slots and associated buffers, but recording, planning and migration stay inactive; this is explicitly custom static residency, not supported upstream EPLB-off. A preinitialized B128 length and inactive recording flag replace per-job native flag/length/history writes. One kernel replaces histogram, home selection and map kernels; its physical-ID buffer is consumed on the same sequential CUDA inference stream before reuse.

The 60-run identical-assignment factorial identified mean package effects of 51.872 µs/job for recording/control and 35.154 µs/job for online selection. These are matched package contrasts, not exclusive GPU-kernel costs. The known-home diagnostic remained slower than stockoff; it is not a claim that runtime below it is impossible.

The bounded fused prototype check added 36 development trials: six old pilot groups × two reverse-order repetitions × three contemporaneous arms (stockoff, current, fused static). Both independent integer references agree with all 18 adversarial case/dtype checks, and captured-input whole-layer checks pass. After averaging technical repetitions per group, fused/current service ratio is 0.892074 and fused/stockoff is 1.021542; every development group remains slower than stockoff. This supports repairing the current path, not claiming superiority over the native-off option. The source, raw evidence and independent audits are retained. There is no additional algorithm search or post-final fallback selection. The full count is 96 development + 264 fresh treatment + 22 baseline calibration executions = 382, with preparation/correctness work separately identified.

Fresh document identities/prefixes and external arrival-row intervals must exclude all earlier selected material. MBPP has one pilot and one final 32-document group as a descriptive sentinel. This narrows the main claim; it does not treat one MBPP group as population evidence. Total fresh material is 320 GSM8K, 320 WildChat and 64 MBPP documents.

The final arms are `stockoff`, `current`, and `fix`. Stockoff remains the unmodified EPLB-default-off configuration within this controlled layer harness, with 128 resident experts. Enabled/custom 160-slot geometry is not relabeled as supported stock EPLB-off. Actual expert residency, extra buffers and process-memory scope are disclosed.

Obtain one native-stockoff-only saturated 4,096-job calibration per content group on the same hardware and coordinator/completion path. ## Treatment order, completion and correctness

For each content group/load, code and conversation cases use exact reversed three-arm orders. In each main dataset/load there are 16 final cases: allocate reverse-permutation pairs 3,3,2, yielding each of six permutations two or three times. Rotate the deficient pair across datasets/loads so each pooled main-load stratum has each permutation five or six times. Within each service/dataset/load, each permutation occurs once or twice. Seeded group/roster shuffling is fixed before timing. This gives exact pairwise precedence balance, but treatment positions are only near-balanced; archive actual counts. MBPP code/conversation also reverse within each load. Pilot uses the analogous balanced feasible allocation for two groups/dataset; no impossible equality across six permutations is required.

Common untimed preparation and conditioning precede reset-state episodes. Real gate/top-k, native kernels/reduction, normal current-method boundaries including the final boundary, coordinator dispatch and ACK are charged. Response ends at current-inference-stream completion after the normal step and ACK. Full observed completion includes the external horizon and any ordinary completion tail; a discard-only drain is never equivalent to normal commit. Keep every job's immutable release, observed admission, start, finish and rank envelopes. Report queue, service, response, p95, completed extent, tail, drain and finite-episode throughput separately; none substitutes for another or for saturated capacity.

Require authenticated capture/job/route/float-weight identities, all 4,112 prepared-batch comparisons against stockoff per group, the declared 64 FP32 token-position checks per group, 16 whole postflight batches per trial, all resident weight/map checks, and independent physical-assignment checks for current and fix. Preserve recorded coverage limits. Fresh state, exact current controller trajectory and inactive fixed-controller state must be audited from raw metadata. Independent record/lifecycle and statistical implementations must pass before interpreting final outcomes.

## Main inference and MBPP sentinel

The main resampling unit is a complete GSM8K/WildChat content bundle containing both arrival types, both loads and all three arms. For each endpoint, average paired log ratios over arrival types within group, groups within dataset, then the two dataset means equally; exponentiate. Compute a trial's p95 before forming ratios. Use 100,000 whole-bundle bootstrap draws, stratified by the two datasets, PCG64/default_rng seed 471712 and linear quantiles. Reuse draw tables across all endpoints. Publish SHA256 of concatenated GSM8K then WildChat `[100000,8]` tables as little-endian int64 C-order bytes without headers. MBPP never enters these draws.

Primary: fix/stockoff high-load mean response, with a two-sided 95% interval upper bound strictly below 0.95. Ten regression guards cover each main dataset/load mean plus aggregate high-load p95 against both stockoff and current (five per control). Each one-sided 99.5% upper bound must be ≤ 1.02; the family uses 0.05/10. Delete each actual main-source date, linking services sharing that date, and recompute high-load point ratios against both controls. Every point must be ≤ 1.02; a missing dataset fails. These deletion checks have no CI and do not estimate new-day variability.

Only after the primary, all ten main guards and main date-deletion checks pass, test fix/current high-load mean response with the same two-sided 95% interval and strict 0.95 upper limit. If the gate closes, its point remains descriptive with no newly inferred secondary interval. The resulting `main_acceptance` is reported separately.

MBPP has one held-out content bundle, not a bootstrap stratum. Six descriptive point checks average its two arrival types: mean response at each load and high-load p95, versus both controls. Each ratio must be ≤ 1.02 to pass the operational sentinel. It supplies no confidence interval or MBPP-population nonregression guarantee. Overall advance requires both main acceptance and the MBPP sentinel; a sentinel failure cannot alter or rescue main inference, and a main failure cannot be rescued by MBPP.

The 5% useful-gain and 2% regression margins are carried-forward engineering criteria, not numerical tolerances or universally established literature constants. Report every outcome and all per-dataset/type/load cells descriptively. A failed upper-bound target is not itself proof of regression; an interval entirely above 1 supports higher response within this conditional design. Uncertainty remains conditional on selected trace material, constructed payloads, the narrowed two-dataset mix and one allocation, not new production days, engines or hardware populations.
