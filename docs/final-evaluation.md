**SkewBench is scientifically sound as a bounded negative-result course project, but the completed study does not support useful incremental value from the two-window TV gate.** On the frozen burst endpoint, B4 did not improve clearly over improvement-only B3 and was slower than the pilot-selected cooldown B5. It beat native B2 by about 3%, which does not isolate TV's contribution. Feasibility is now demonstrated for the explicitly synchronous, replicated-input layer harness; novelty remains a modest admission-policy ablation.

The final allocation completed normally in 38 minutes 31 seconds, with **1,400 valid policy runs, eight valid decision pairs, and no missing or invalid records**. The primary result is a failed practical-benefit criterion, not a software failure. Ratios below one mean B4 completed faster.

The proposal already contained unusually useful controls for a course project: paired inputs, fixed replica resources, an improvement-only comparator, a no-move control, completed elapsed time, pilot/final separation, correctness checks, and permission for a negative finding. The evaluation preserved these and added one cooldown baseline plus eight identical-state decision replays. It did not expand into a model, hardware, or serving benchmark survey.

**What was actually tested**

One allocation contained two NVIDIA H100 94 GB GPUs connected by NV6. The layer used the actual pretrained expert tensors from Qwen3-30B-A3B layer 0: 128 logical experts, top-8 routing, hidden width 2,048, intermediate width 768, BF16 SwiGLU, and 32 additional replicas. Both ranks replayed the same synthetic logical top-k routes and combining weights, with seeded Gaussian hidden states. The native fused MoE kernel computed local experts; NCCL all-reduce combined outputs. Native `torch_nccl` transported expert weights. This is a replicated-input layer experiment, with one hidden-state tensor reused across the routing sequence, rather than a natural-text or token all-to-all serving workload.

All five methods used the same 160 physical slots, initial map, eligible GPU resources, and native placement planner. B2 admitted native proposals; B3 added the 2% predicted peak-load improvement threshold; B4 additionally required adjacent-window TV at most 0.1; B5 added a 256-step cooldown to B3. SKIP returned the current map at the same admission point, so it still paid native observation, planning, and no-op handling costs. B0 and B1, without extra replicas, were retained as small contextual pilot controls and were not confirmatory endpoints.

The frozen matrix contained seven trace cases, two batch sizes (128 and 1,024 tokens), ten independent held-out trace seeds, and two technical repeats: 1,400 runs. The cases were stationary skew, uniform demand, brief recurring bursts with two fixed phases, one persistent change, and periodic switching with two fixed phases. Each measured horizon contained 512 steps after 32 untimed observation steps. Windows contained 16 steps; proposal cadence was 64 steps. The fresh proposal after the final input was suppressed before planning, leaving seven measured opportunities. These short windows and cadence deliberately exercise the gate; they are not vLLM defaults.

The single cooldown was selected from 64, 128, and 256 on disjoint pilot seeds. All three met the pilot stationary constraint and lay within the predeclared 1% tie band; the rule chose the largest, 256. This does not establish a uniquely optimal cooldown. Final thresholds, trace geometry, repetition count, and margins were frozen before held-out measurements. Implementation corrections and superseded pilots are preserved in the execution record, including removal of an accidental CUDA histogram synchronization and initialization of lazy weight transport before measured runs.

The primary timer measured completed elapsed wall time on the slowest rank, including online observation, planning, gating, native transfer, normal commit, instrumentation, and final CUDA completion. Model loading, compilation, declared warmup, tape export, and independent correctness checks were outside that timer. A throwaway native cross-rank transfer and rollback initialized the same transport process group before any measured run; every subsequent admitted transfer was charged. Step CUDA events and host phase regions are explanatory records, not additive components of wall time. No isolated transfer-latency or profiler-derived bottleneck claim is made.

**Decision information versus policy effect**

B4 versus B3 estimates the total effect of adding the gate. Later mappings and candidates may diverge because earlier decisions changed the state; that is part of the policy effect. It does not identify whether TV itself separates profitable from unprofitable moves. B4 versus the frozen B5 asks whether its state-dependent restraint outperforms one simple frequency control. B4 versus SKIP checks whether this policy's migrations repay their full costs relative to this no-move control in this bounded setting.

Eight diagnostic states were fixed in advance: the first proposal on a common B3 trajectory for stationary, burst, persistent-change, and periodic core traces, at each batch size. Each snapshot restored the same actual weights and map before forced allow and forced skip, replayed the same next 128 steps, and disabled later rebalancing in both arms. Allow included native migration and commit cost. Four pairs ran allow first and four skip first. Realized payback is `skip elapsed − allow elapsed`; positive values favor the move. These are eight descriptive counterfactuals, not a fitted predictor, an independent population accuracy estimate, or proof about longer horizons.

All eight candidates were improvement-eligible. Every forced move lost time over the fixed 128-step future, including the two low-TV moves B4 would allow. B4 rejected six losing moves but retained two losing moves. The diagnostic set therefore contains no profitable move with which to demonstrate preservation of useful migrations. It cannot estimate general discrimination accuracy or a profitable-move rejection rate.

Burst and persistent-change cases had exactly the same past routes, combining weights, logical windows, source state, candidate, and gate decision at step 63. Their futures first diverged at step 72. Both measured paybacks were negative, so these results do **not** demonstrate rejection of a profitable persistent-change move. In the full policies, B4 nevertheless deferred the first persistent-change remap from step 63 to 127 in all 40 matched cases. The secondary persistent B4/B3 ratio was 1.0088 [1.0033, 1.0151]; that is the whole policy effect, not an isolated estimate of delay cost.

[Branch records and audit](https://github.com/hsylin/cs471/blob/main/results/final/audits/final-branch-correspondence-audit.json). Each state has one allow/skip pair, so the millisecond values remain descriptive and have no per-state confidence interval. Losses at H=128 do not rule out repayment later in the longer policy horizon.

The rule has three mathematical limits independent of the results. Normalization discards absolute demand: proportional count scaling leaves TV and relative predicted improvement unchanged even when token work and fixed migration cost change their relationship. A histogram loses within-window order: a switching trace can present equal adjacent histograms despite changing hotspots. A persistent change initially raises TV, potentially rejecting a move exactly when its future benefit begins. The two batch sizes, phase shifts, and persistent trace probe these limits, but do not exhaust them.

Observed stationary TV medians were 0.03635 and 0.01260 at 128 and 1,024 tokens, respectively. None of the 140 observed decision windows per batch exceeded tau=0.1. Those repeated windows are correlated and are not 140 independent Bernoulli trials. Sampling noise was visibly batch-dependent, but false stability alarms did not explain the stationary regression at this threshold.

The phase stress test exposed histogram aliasing: periodic core traces had median TV about 0.785 and B4 rejected all 280 opportunities across the two batches. Shifting by eight steps reduced median TV to about 0.0388/0.0135, below threshold at every opportunity, despite continued switching. The improvement gate still rejected 116/140 and 120/140 opportunities in those shifted cases. Thus low TV did not automatically cause migration; the proposal's existing improvement control mattered.

Across 9,800 recorded windows, the largest equal-sharing rank-load-share error was 0.01039, or 1.04 percentage points. Even an accurate token-load approximation would not validate a runtime proxy: the branch candidates predicted 8.04%–20.43% peak-load improvement yet every move lost time over H=128. On core bursts, B4 reduced average sender payload relative to B3 by about 1.79 GB/run at 128 tokens and 1.23 GB/run at 1,024, without an established completed-time gain in either cell. These observations directly show why fewer bytes and predicted token-balance gains cannot stand in for speedup. No profiler-based attribution to memory, compute, or transport bottlenecks was established.

**Overlap with primary literature**

Migration awareness is established as a design concern; the distinct hypothesis here is the incremental value of this particular historical statistic with the planner held fixed. Gimbal combines placement and frontend scheduling and penalizes migration from current placement. That is a movement-cost regularizer, not an adjacent-distribution stability test. FreeBalance predicts upcoming expert loads from residual streams and constrains swaps using transfer and overlap budgets; it uses different information and a different intervention. Its fixed-swap comparison reinforces the need for a simple restraint control. Neither paper establishes SkewBench's exact TV rule. ([Sun et al., Gimbal](https://doi.org/10.48550/arXiv.2606.15177); [Chen et al., FreeBalance](https://doi.org/10.48550/arXiv.2608.14205))

Token balance is not a sufficient runtime objective. METRO changes replica dispatch while retaining placement and replication, reporting that token balancing can activate excess expert weights in memory-bound decode. It also changes token transport to all-gather, so its whole-system gains are not a pure dispatch-objective ablation. TEMPO includes activation, token work, and tile padding in its runtime model. These are reasons to compare realized completion times and physical dispatch with the equal-sharing proxy; they are not evidence that historical stability predicts migration payback. METRO's hardware measurements and proprietary simulator results, and TEMPO's modeled and hardware results, must remain distinct. ([Yu et al., METRO](https://doi.org/10.48550/arXiv.2512.09277); [Li et al., TEMPO](https://doi.org/10.48550/arXiv.2608.13057))

The reviewed versions were METRO v1, Gimbal v1, TEMPO v2, and FreeBalance v1. They are cited as preprints/manuscripts; Gimbal names ATC 2026 in its manuscript, but proceedings publication was not independently established. No runnable public artifact was validated: TEMPO's linked repository returned 404 and the other reviewed fulltexts provided no located runnable artifact. Their performance results were not reproduced here. No exact two-window TV gate was found in this bounded comparison, which identifies a distinct empirical question without establishing priority.

**Five consequential weaknesses**

1. **Incremental utility is unsupported. Necessary claim correction.** The useful-gain tests fail against both B3 and the one frozen cooldown. A native-only win would overattribute the improvement gate's benefit to TV. Present the result as a negative admission-policy evaluation; this does not invalidate the experiment.

2. **Decision discrimination remains underidentified. Necessary limit; optional follow-up.** All eight branch moves lose time at H=128. Low historical TV did not ensure positive payback in these measured replays. They cannot show that TV preserves profitable moves or establish a population classifier. One-shot branches also leave local timing uncertainty unresolved.

3. **The statistic discards information needed for payback. Necessary operating-boundary statement.** Absolute demand, within-window order, and future hotspot lifetime are absent. Noise calibration, phase shifts, and persistent-change traces were necessary fixes and are now present. They revealed aliasing and a 64-step adaptation delay. No claim about that delay's isolated runtime cost is warranted.

4. **The placement proxy is not a latency model. Necessary measurement fix completed.** Actual replica dispatch differs from equal sharing, and predicted peak-load gains did not ensure positive branch payback. Completed time, actual counters, sender payloads, and identical-state replays address this problem without adding a learned cost model. Transfer/commit costs are included in completion timing but are not separately isolated on a profiler timeline.

5. **External validity and external replication remain limited. Necessary scope statement; optional integration.** The result concerns one synthetic layer workload, synchronous native EPLB, a replicated-input/all-reduce path, short fixed windows, and the fallback fused-MoE kernel configuration. Numerical checking covers four token outputs at each final placement. Ten seeds and eight selected states do not represent production traffic. Full-model serving, asynchronous overlap, other hardware, and broader correctness fault injection are optional extensions, not prerequisites for this bounded negative result. An independent human replication remains outstanding.

**Scientific soundness: sound within the declared experiment. Incremental novelty: modest and empirical. Feasibility: demonstrated for the selected synchronous path. Six-week suitability: good, with the negative finding retained.** The necessary fixes were the consecutive-window/commit contract, one frozen cooldown, actual payback replays, all-overhead timing, and declared uncertainty and margins; they have been implemented and tested. The gate does not merit a speedup or useful-selector claim from these results.

The experiment that changed the initial tentative assessment was the frozen cooldown comparison together with the same-state payback replay: the selected cooldown outperformed B4 on the frozen burst endpoint, and low TV did not identify a paying move in the sampled states. If one optional follow-up is added, the most informative would be the same-state replay at one longer horizon chosen and frozen on pilot data, with held-out candidates spanning profitable and unprofitable pilot strata. That could change the assessment of decision information because the current diagnostic set has no positive-payback case. It would not erase the failed primary criterion for the completed 512-step policy study. Full-model integration can remain optional.
