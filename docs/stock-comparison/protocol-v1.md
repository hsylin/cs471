# Stock-layer comparator protocol

**Prespecified protocol, frozen with its execution manifest before treatment timing.** The genuine-layer apparatus smoke completed without performance-selection use; its correctness record is separate from pilot/final timing evidence. Previous experiments and their source files remain immutable. The earlier forced-SKIP comparison does not establish a gain against unmodified vLLM.

## Question and comparators

The question is whether the existing method improves arrival-to-completion latency of a fixed-token Qwen MoE layer job against two actual supported vLLM configurations on the same two H100s. This is a layer experiment, not a full model, chat request, TTFT, token-generation, dynamic-batching or production-service evaluation.

All arms execute the actual pinned vLLM Qwen3 sparse-MoE block/FusedMoE implementation, including its normal gate and top-k computation. Replay supplies authentic fresh hidden states, not injected HuggingFace expert IDs or combining weights. All arms use the same native output-reduction policy and automatic backend selection. Exact chosen backend, kernel configuration, routing dtype/normalization and collectives are archived. The old NativeLayer wrapper is not relabeled as a stock baseline. Numerical and routing checks must authenticate the actual stock operation; captured historical routing is not a substitute.

The three arms are:

| Arm | Configuration | What is held or changed |
|---|---|---|
| `stockoff` | Unmodified pinned vLLM, EPLB disabled | Supported stock default;128 physical experts,64 per rank; no artificial recorder or forced-SKIP controller added. |
| `stockon32` | Unmodified pinned vLLM, EPLB enabled with32 redundant experts | Explicit replica-budget setting; native window1000, interval3000 and asynchronous behavior remain at pinned defaults; real proposals/migrations/commits are allowed. No AdmissionPolicy override. |
| `ours` | Existing combined policy ported to the same actual stock block |160 resident slots, current fixed map, resident mapper, unchanged-map shortcut, and its existing window16/interval64 forced-SKIP controller. All of those costs remain charged. No silent controller-free improvement or map-general algorithm is introduced. |

`stockon32` is a configured stock system, not the entire shipped-default configuration: enabling EPLB and setting redundancy32 are explicit changes, while its controller mechanics and default window/cadence/async mode remain native. Disabling EPLB with nonzero redundancy is rejected by the pinned API, so stockoff legitimately uses no redundant slots. All arms receive the same physical GPUs and maximum memory allowance; actual resident weights, buffers and peak memory differ and are reported. This is equal hardware opportunity, not identical memory residency. Stockoff must not be burdened with unused replica maps or recording to manufacture resource equality.

The measured claim is superiority to both **tested** stock configurations. It is not superiority to every legal vLLM configuration; enabled EPLB with zero redundancy and other tuning choices are untested. Stockoff remains the primary comparator even if stockon32 is slower. No post hoc choice of the weaker comparator is permitted.

## Calibration and matrix

Obtain one fresh native-only saturated stockoff calibration per content group using the same real layer, gate, output reduction, per-job completion and coordinator path as the treatment runs. Calibration includes4096 completed jobs, with `C=4096/(last_completion−first_start)`; the denominator includes between-job server bookkeeping. This is a capacity estimate, not mean isolated kernel time. Calibration records never become treatment replications. Neither ours nor stockon32 performance determines the arrival rate.

For each content/arrival-type case, scale original offsets by one exact rational factor to offer loadρ=0.5 or0.85 relative to its stockoff capacity. Preserve relative timing and ties subject to documented integer-nanosecond rounding. All three arms share the resulting immutable calendar. Freeze derived calendars after baseline-only calibration and before any treatment execution. This normalization defines the tested loads; it does not claim a common absolute request rate across different content groups.

Final size is fixed at six groups per dataset; pilot timing cannot choose dataset, final group, comparator, cadence, rate, algorithm or sample size. Pilot may establish correctness and apparatus feasibility; a failure requires an explicit amendment and preserved failure records, not silent replacement. No performance fallback is prespecified.

Assign all six three-arm permutations equally within each load. In the final matrix, also balance them within each dataset/load stratum, which has12 cases and therefore two of each permutation. ## Timing and correctness

Release times are external absolute wall-clock offsets, never shifted when execution falls behind. Preserve all jobs and drain the queue. Record intended arrival, observed admission, command start, completion and both ranks' completion envelopes. Common coordination overhead remains charged in every arm. Stockoff is not charged for instrumentation absent from the stock execution path; detailed architecture observations belong in separate untimed replays or native counters that the arm itself uses.

Each job ends after its GPU output completion and the common CPU ACK barrier; ordinary response is coordinator finish minus immutable arrival. No extra asynchronous-controller flush is added to each job. After the last output, ordinary native readiness and movement-to-workspace complete every pending cycle without discard; both GPUs synchronize and a CPU barrier precedes the coordinator quiescent timestamp. The coordinator then waits through the full external horizon. `job_completed_elapsed_ns` is last output finish minus epoch; `completed_elapsed_ns` is final observation end minus epoch and includes both normal controller quiescence and any remaining offered-load horizon. `controller_tail_elapsed_ns` is quiescent minus last output finish, while `quiescence_call_elapsed_ns` starts immediately before the normal completion call. Neither is an exclusive controller/GPU cost. Preserve per-rank tail timestamps, actual completed work, horizon backlog and both output-only and controller-inclusive drain. Faster host return from a shared barrier is not treated as a cross-rank completion discrepancy.

Verify input hidden-state/weight identity, actual stock gate/top-k routing and combining weights, expert mapping legality, output tolerances, rank agreement, native decision-window scaling, transfers and committed maps. Stockoff and ours have different physical counts; compare logical computation and numerical outputs, not identical physical layout. Ours must retain its fixed map and make no movement; stockon32 may change maps and weights through the native path. Its post-migration computation must be checked against the appropriate logical expert weights. All floating tensor hashes use explicit floating encodings, never the integer-array helper. All4112 unique prepared batches (16 excluded warmup plus4096 measured) are checked against stockoff before timing; four designated batches at raw indices16,765,3765,4111 additionally check16 positions each against dense FP32. Sixteen evenly spaced whole measured batches are checked after every trial, alongside every resident physical expert weight and inverse-map identity. This is sampled post-migration numerical coverage, not a full-output FP32 proof. Ours' physical assignments are checked against the independent CPU selector on all4112 inputs. Peak allocation includes all simultaneously resident comparator objects and prepared inputs/references; it is not standalone-engine memory. Per-arm resident parameter bytes are reported separately.

## Prespecified inference

Statistical helpers consume verified complete run-level pairs. For each content group, average paired log mean-response ratios over its code and conversation trials at the designated load. Average group scores within each dataset, then the three dataset means equally, and exponentiate. A trial's p95 is computed from its4096 finite-trace responses before forming a ratio. Jobs and controller steps are not uncertainty units.

Use100,000 whole-content-bundle bootstrap draws, stratified by dataset, with NumPy PCG64/default_rng seed471612 and linear quantiles. Each stratum has six groups. Reuse the same draw tables for every endpoint and contrast, retaining both arrival types, both loads and all arms within each sampled group. Publish the little-endian int64 draw-table digest. These intervals are conditional on the selected trace material, constructed content sampling and one hardware allocation; they do not quantify unseen-calendar or production-deployment variation.

Primary: `ours/stockoff` mean response atρ0.85, with two-sided95% interval upper bound strictly below0.95. Fourteen symmetric regression guards cover each dataset/load mean response plus aggregate high-load p95, relative to each of stockoff and stockon32: seven per control. All one-sided percentile upper bounds at `1−0.05/14` must be at most1.02. This family is deliberately conservative with only six groups per dataset; it is not relaxed after observing pilot or final results.

Delete each actual calendar date in turn, linking code/conversation records on a shared date. For each control separately, recompute the high-load mean-response point ratio using remaining arrival types within each surviving content group, surviving groups within each dataset, and equal dataset weighting. If a dataset disappears the check is not estimable and fails. Every deletion must remain at or below1.02 relative to both controls. These are finite-design robustness checks, not confidence intervals or claims about new days.

Only after the stockoff primary, all14 guards and all date-deletion checks pass, test `ours/stockon32` high-load mean response as a hierarchical secondary, using the same95% interval and strict0.95 upper bound. Overall “usefully faster than both tested stock configurations” requires that secondary too. If the gate closes, its point estimate remains descriptive and no secondary confirmation is claimed. Stockon32/stockoff, all per-dataset/type/load cells, service/queue decomposition, architecture and controller associations are descriptive. No test is rescued by lower active-expert counts without completed-response benefit.

A failed upper-bound requirement is a failure to establish the target, not automatically proof of regression. The report must include every completed trial and failure, all comparator results, actual memory/replica asymmetry, both loads, async state behavior and conditional inference limits. The5% useful-gain and2% regression limits are carried-forward engineering margins chosen before this study, not numerical tolerances or universal literature constants.
