# Implementation audit: actual stock-layer comparison

The comparator instantiates the real `Qwen3MoeSparseMoeBlock`, its `MoERunner`, gate, router and routed-expert method from vLLM commit `db9527a46873454610df6dbedf79a36d6bf1a7f6`. It does not relabel the previous direct-kernel `NativeLayer` as stock vLLM. The facade verifies 35 selected installed source files against pinned SHA256 values before construction. The source implementation and its instrumentation tests were introduced in commit `bd49f2d`; the execution manifest records the complete study source identity.

“Unmodified” describes the tested stock algorithms and actual module path, not an uninstrumented full vLLM server. The external harness initializes groups, supplies one layer's checkpoint weights and hidden inputs, establishes native forward contexts, calls EPLB, records clocks and lifecycle metadata, and completes pending work at the finite-input boundary. It does not run attention, a full decoder, dynamic batching, CUDA graphs or the vLLM request scheduler. Both GPUs receive the same token batch; this TP2+EP, DP1/PCP1 configuration does not exercise token all-to-all dispatch. Native output reduction remains common to all arms. [Qwen block construction and forward](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/models/qwen3_moe.py#L133-L239), [parallel configuration](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/fused_moe/config.py#L1182-L1229), [native output reduction](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/fused_moe/runner/moe_runner.py#L480-L514).

## Exact differences

| Arm | Resident experts | Controller and physical assignment |
|---|---:|---|
| `stockoff` |128 total;64/rank|EPLB disabled; no artificial observation/controller calls. Original stock logical routing and local expert ownership. |
| `stockon32` |160 total;80/rank|EPLB enabled with 32 explicitly configured replicas. Original default planner, native physical hash assignment and asynchronous movement/commit; window 1000, interval 3000. |
| `ours` |160 total;80/rank|The same stock gate/top-k, experts and output reduction, with the frozen resident-selection instance hook, existing forced-SKIP admission policy, synchronous window 16/interval 64 control and scoped unchanged-map shortcut. These costs remain charged. |

Stockoff cannot legally retain 32 redundant experts with EPLB disabled: the pinned configuration rejects that combination. Stockon32 is therefore a supported configured stock comparator, not every shipped default. The comparison changes the complete tested policy/configuration; it does not isolate only dispatch or only the shortcut. [Replica constraint](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/config/parallel.py#L533-L562), [EPLB defaults and async constraints](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/config/parallel.py#L61-L116).

Each BF16 expert occupies 9,437,184 bytes: two 2048×768 matrices in the gate/up projection and one 768×2048 down projection. Expert parameters therefore use 576 MiB/rank for stockoff and 720 MiB/rank for the other arms, 25% more. The shared logical gate adds 0.5 MiB/rank. Enabled EPLB also allocates a full local expert receive buffer; Gloo stages transfer tensors on CPU. Equal GPUs and memory allowance do not mean equal memory residency. Process peak allocation includes all simultaneously resident comparator objects and prepared inputs/references, so it is not standalone-engine memory. [Weight shapes](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/fused_moe/unquantized_fused_moe_method.py#L65-L138), [native receive buffer](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/eplb/eplb_state.py#L475-L490).

## Authentic computation and resolved backends

Replay supplies BF16 hidden vectors only. Each timed call computes the checkpoint gate and native softmax/top-k. The stock top-k allocates float32 combining weights; earlier HF captures stored BF16-rounded scores as float32, which is a different numerical contract. Historical expert IDs/weights are not injected here. Untimed checks use the actual stock gate/top-k and verify equality across arms. The standard stock weight postprocessing runs before collecting native EPLB weight pointers. [Native gate execution](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/fused_moe/runner/moe_runner.py#L900-L925), [float32 top-k weights](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/fused_moe/router/fused_topk_router.py#L85-L130), [native weight-pointer registration](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/models/interfaces.py#L1030-L1062).

The native SM90 unquantized preference selects Triton. Both E64 and E80 smoke paths reported missing tuned H100 configuration files and used native defaults. `resolved_kernel_config` records the unchanged selector result using the actual weight shapes, batch size, top-k and quantization namespace; a nonempty global override is rejected. This is not an optimized-H100 or best-backend claim. [Native backend preference](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/fused_moe/oracle/unquantized.py#L50-L96), [modular Triton selector call](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/fused_moe/experts/triton_moe.py#L301-L315).

Native output reduction tries hardware- and input-dependent backends. The smoke log records unavailable symmetric multicast and unsuccessful FlashInfer workspace initialization on this NV6 pair; those messages alone do not identify the backend that ultimately returned the output. An untimed, delegate-only probe records candidate reduction methods that actually return a tensor, restores all instance hooks immediately, and archives disabled flags. No candidate is forced during primary timing. [Native dispatch/fallback chain](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/device_communicators/cuda_communicator.py#L335-L408).

Smoke-v2's archived rank 0 probe observed `ca_comm` (`CustomAllreduce`) returning the output for BF16[128,2048]. It did **not** select the old harness's explicit torch-NCCL reduction. FlashInfer and symmetric-memory candidates were disabled; PyNccl was available but was not selected by that probe. Both ranks' snapshots record the same candidate states. All three arms, on both ranks, resolved `BLOCK_SIZE_M=64`, `BLOCK_SIZE_N=128`, `BLOCK_SIZE_K=64`, `GROUP_SIZE_M=1`, `SPLIT_K=1`, `num_warps=4`, `num_stages=3`. These are observed defaults, with no tile override. See [smoke-v2](../../results/stock-comparison/smoke-v2/smoke.json). The primary runner additionally gathers both ranks’ probe records and requires their successful backend lists to agree; each run archives that evidence.

## Native scheduling, completion and reuse

Stockon32 uses the observed native `TorchDistGlooStagedEplbCommunicator`; this is the automatic static-EP fallback when NIXL is unavailable. It stages GPU sends to CPU, performs Gloo communication and copies receives to GPU. Payload divided by its elapsed time is not NVLink bandwidth. Ours retains its explicitly synchronous `TorchDistNcclEplbCommunicator`, although forced SKIP plus the shortcut produces no migration. [Automatic transport selection](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/config/parallel.py#L1051-L1069), [Gloo staging](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/eplb/eplb_communicator.py#L156-L241).

Measured stockon32 starts at the native counter 2250, giving a first opportunity after 750 step calls and nominally another after 3750. The first history contains 750 valid observations; the ordinary second contains 1000. Pending native work may defer a subsequent launch; actual sampled indices, launch counters, deferred steps, committed maps and completion points are retained rather than excluding a slow baseline. Ours starts at 0 and keeps all 64 opportunities in 4096 jobs, including the final one. [Native startup](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/eplb/eplb_state.py#L461-L465), [recording and deferred launches](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/eplb/eplb_state.py#L639-L709).

Every enabled forward charges native `prepare_forward` and subsequent `step`. The primary job ACK waits for the inference stream, not a device-wide wait that would also serialize already-enqueued async migration work. Main-thread native commits executed inside `step` remain charged to that job. After the final output ACK, the tail polls native all-rank readiness and calls native `_move_to_workspace`, then performs device-wide synchronization and a common barrier. This completes actual weight/map commits without advancing cadence or inventing new proposals. Output response and controller-inclusive completion are reported separately. `drain_async` is never used: upstream explicitly discards transferred work in that method. [Prepare call](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/eplb/eplb_state.py#L520-L554), [discarding drain](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/eplb/eplb_state.py#L985-L1015), [normal commit and ACK](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/eplb/eplb_state.py#L1418-L1443).

One persistent stockon32 worker is reused, rather than creating a daemon per trial. After normal consumption, the single-layer worker does not reread old statistics before its next launch. Canonical untimed resets restore checkpoint weights/maps, zero observation history and restore the declared startup counter; no history carries between trials. A once-per-process 750-step real native cycle warms asynchronous transport before measurement, followed by normal completion, weight/map audit and reset. Every trial then has the separately recorded 64-step conditioning/reset. These define a warm-process, reset-state estimand. [Worker lifecycle](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/eplb/async_worker.py#L74-L159).

One native edge case matters to independent auditing: commit updates the maps without remapping old physical-history rows. If a very late changed-map commit overlaps a sampled window, native logical planner counts must be reconstructed from each input's actual physical assignment and the map used at aggregation. They need not equal a simple sum of true logical IDs. Such native behavior is reported, not treated as grounds to remove a slow trial. [Aggregation](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/eplb/eplb_state.py#L790-L825), [map-only commit](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/distributed/eplb/eplb_state.py#L1344-L1377).

## Observed apparatus evidence and remaining scope

Smoke-v1 completed 4096 repeated-input jobs per arm and exited successfully. Stockoff had no controller, map changes or payload. Stockon32 launched at 749/3749 and committed at 864/3752; its recorded global window totals were 1,536,000 and 2,048,000 assignments, exactly 750/1000×128×8×2. The changed first cycle sent 245,366,784 bytes on rank 0 and 254,803,968 on rank 1; the second repeated-input cycle sent zero. Both ranks ended with cleared pending state and checkpoint-consistent committed maps/weights. Ours retained the initial map, made 4096 mapper calls and 64 shortcut movement/commit pairs, and sent zero bytes. This validates a real changed-map native cycle, not performance on the final workloads. The smoke checks full-batch output agreement at seven specified steps and after completion; its independent FP32 reference covers 16 tokens of the initial batch, not all 4096 outputs. The artifact is [smoke-v1](../../results/stock-comparison/smoke-v1/smoke.json). Smoke-v2 repeated all three functional paths with the final cycle-byte counter and resolved-backend instrumentation: stockon32 committed at 857/3753, with the same window totals and actual sender payloads, and both ranks passed resident-weight/map checks. The smoke uses device-wide waits for functional checking and supplies no timing evidence; the primary harness uses the inference-stream completion boundary described above.

Instrumentation is part of the harness. Native sender payloads are counted transparently; async counts are keyed to retained native cycle objects so a commit and next launch in one step cannot mix byte totals. Recorded sampling indices, CPU decision metadata, occasional GPU map snapshots, clock/dispatch/ACK work and our controller diagnostics consume time. The stock planner/router/movement/commit implementations are not replaced to obtain those records. Five CPU tests cover cycle-accounting separation and reduction-probe restoration, including failure. Full-study preflight and postflight checks are specified in the [protocol](protocol-v1.md); passing them establishes the stated numerical/map coverage, not a separately reproduced GPU execution, an all-output FP32 proof, production request latency or superiority to every legal vLLM configuration.
