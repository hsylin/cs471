# Fresh workload provenance for the stock-vLLM comparison

This workload contains **768 fresh source documents**, arranged into 24 groups of 32 documents: two pilot and six final groups for each of GSM8K, MBPP and WildChat. It also contains **48 fresh arrival intervals**, each with 4,096 job rows and one following boundary row. The workload changes content and source rows while retaining the pinned Qwen3-30B-A3B checkpoint, layer 0, and the declared two-GPU experiment. Freshness is relative to this project's earlier selections and captures; it does not establish absence from model pretraining, semantic independence, or new production services.

## Source versions and terms

The original downloaded bytes and terms are reused, with SHA256 checks before selection. The public manifest stores every input byte count and digest. Raw text and token IDs remain in the private capture manifest; public artifacts retain source IDs, selected-token counts, hashes, exclusion decisions and provenance.

## Exclusions and fixed selection

The exclusion inventory includes all three earlier generalization selections, including superseded selections and unused held-out groups. Their union contains 1,927 unique documents: 640 GSM8K, 640 MBPP and 647 WildChat documents. It also includes **56 earlier captured source documents in 28 two-document banks**, from the followup, optimization and resident-dispatch corpora. These are source-document counts, not 56 banks.

Source IDs, Unicode-NFKC/casefold/whitespace-normalized text, and normalized model-visible prefixes are checked. Near duplicates have Jaccard similarity at least 0.8 over sets of five regex-word/punctuation shingles. All prior reference views remain indexed even when mutually similar. Historical long sources contribute their actual first 2,048 captured tokens, their common first-512-token view, and a normalized whole-source exact hash. Candidates are deduplicated before pilot/final assignment; complete earlier books are not compared approximately to every short prompt. These checks do not exclude shared short fragments or semantic paraphrases below the declared threshold.

After eligibility and exclusions, the available fresh pools contain 679 GSM8K, 329 MBPP and 2,304 WildChat documents. This is why 32-document groups are used: MBPP cannot supply eight additional groups of 64 within this pinned source frame. Each dataset contributes exactly 256 selected documents. Identifier/text-hash ranking uses seed 471601. No expert routing, hardware counter or performance outcome enters selection. The rejected-candidate inventory remains archived; 381 WildChat candidates fail the eight-token minimum.

The accepted manifest is `results/stock-comparison/content-v2/source-manifest.json`, with private canonical selection hash `6020e89fc0b814460c6e2b4c2e9423a6956f390ca850cfe96d45cfe5687ef20f`. The earlier content-v1 preparation accidentally retained the old study's schema name and was superseded before capture. The correction changes the study schema/provenance, not the selected document/token blocks. That unmeasured attempt remains archived.

## Authentic capture and constructed jobs

The capture script loads the pinned checkpoint's BF16 embedding, layer-0 attention, normalization and gate tensors. It executes the pinned Transformers decoder, replacing only the expert-computation observer, and checks the captured boundary against a direct attention/residual/norm call. Native router recomputation, its normalization/rounding formula and the hidden-state BF16 serialization roundtrip must agree exactly. Model/source tensor, tokenizer and implementation hashes accompany each bank. These checks authenticate the source inputs; they do not establish the later vLLM execution's numerical correctness.

Measured execution receives **only the exact captured hidden vectors**. The captured HuggingFace expert IDs and rounded combining weights are provenance, not injected routes: stock vLLM computes its own gate, top-k and combining weights during each measured forward. The legacy bank `domain_ids` field means prompt-index modulo two, solely for serialization compatibility; it is not a semantic domain or statistical stratum.

The job builder uses 16 warmup jobs plus 4,096 measured B128 jobs. Seed 471603 and the content-group identity determine a fresh permutation of authenticated record indices per job. The 4,112 unordered combinations must be distinct, and a record cannot occur twice within one job. Records recur across jobs. Each trial therefore executes 524,288 measured token-record occurrences, not 4,096 independent requests. The selected groups contain 1,767–2,127 GSM8K records, 492–542 MBPP records and 2,413–4,909 WildChat records, so MBPP reuse is especially substantial. Exact per-record reuse counts and job-index hashes are recorded by the input builder. Document IDs, original token positions and prefix provenance remain recoverable.

## Arrival rows and calendar limits

The selector scans the full pinned CSVs: 16,803,695 code rows and 27,303,999 conversation rows. Their SHA256 values are respectively `71de5c55cbc35f8f1ed0b6b7806b4cd1e9764b0058469725a6aac98023a1448f` and `a0cc9b969a9bbf0fd811802cbf4323edd3a209ace791e3799ad4f9207f213941`. Timestamp inversions, source-byte changes, negative length metadata and insufficient daily capacity fail selection. Day boundaries are never crossed.

Each candidate comprises 4,097 contiguous rows: 4,096 releases and the following boundary that fixes the horizon. All 92 previously selected arrival intervals, including their boundary rows and unused candidates, are excluded before ranking. The new frame has 4,096 code bins and 6,660 conversation bins; respectively 52 and 47 intersect earlier intervals. Seed 471602 selects bounded identifier-hash winners within each date, without selecting on burstiness or timing. A selected nonpositive horizon/terminal gap fails; it is not silently replaced. The 48 assigned blocks use 196,656 distinct source rows including boundaries, with no overlap against earlier or other new blocks.

Each content group receives one code and one conversation block, reused across the two declared offered loads and all compared arms. The manifest preserves all original offsets, ties, boundary timestamps, lengths and exact source-row hashes. Code dates remain May 10–16, 2024 and conversation dates May 12–18. The first two dates per service are pilot dates; the remaining five are final dates. These are fresh rows from **previously observed public weeks**, not fresh production days or a global future-date holdout. The service-specific splits overlap in calendar date.

Azure supplies no matching customer text. One source timestamp releases one preassembled fixed-token layer job; original context/generated lengths are retained metadata rather than executed request lengths. Pairing these calendars with independently selected prompts cannot recover the original content–arrival dependence. Baseline-only capacity calibration and immutable exact-rational calendar scaling are specified in the experiment protocol.

## Verification boundary

`scripts/audit_stock_comparison_data.py` separately reconstructs exact text/token identities, brute-force length-filtered duplicate comparisons, candidate hash winners and selected source rows. It imports no production selector. Its audit checks 768 selected documents against all 1,927 earlier document identities and 56 historical captured sources, plus all 48 intervals and their boundaries against the full raw CSVs. Focused tests exercise source-ID, full-text, prefix, near-duplicate, boundary-overlap, insufficient-capacity, changed-byte, missing-day and inverted-time failures. This is independent implementation within the same team, not external-laboratory reproduction. Capture and timed-runtime audits remain separate obligations.
