Six-session full-model results

We have not demonstrated an equal-work end-to-end speedup over unmodified vLLM with EPLB OFF. LongBench responses are 4.02% slower with identical generated answers. NuminaMath responses finish 10.65% sooner, but generate 10.71% fewer tokens and show essentially unchanged normalized decode duration. Against EPLB ON, NuminaMath provides a favorable preliminary signal, while LongBench does not. One group per workload cannot establish reproducibility or statistical superiority.

All six sessions completed on the same eight H100s using the complete pinned Qwen3-30B-A3B model. All 96 measured HTTP requests and 96 warmup executions completed. There were no recorded preemptions. Runtime/source admission and independent raw-timestamp arithmetic checks passed. The final collection verified 218 public files against stable cluster bytes and 47 executing source files against commit 605caea3b4d83faee8ccaa6ad372272c94947ab1. The method and frozen workload were not changed after measurements began.

Each table uses the same 16 prompts and absolute arrival times across methods. Response means scheduled arrival to completed response, including client delay, server waiting and generation. TTFT means scheduled arrival to first nonempty streamed content. Elapsed includes the offered arrival horizon and drain; it excludes separately recorded server startup, warmup and teardown. This is warmed full-model HTTP serving, not a deployment-total or sustainable-capacity benchmark.

What is and is not established

Verified: identical paired prompts/calendars/settings within each workload, successful full-model completion, intended direction of request-phase dominance, raw-timestamp reconstruction, source/hardware identity, and all retained negative outcomes. Prior admission checked duplicate weights throughout the model and representative expert arithmetic; it did not prove all full-model logits or semantic answer equivalence.

Not established: a reproducible speedup over OFF, general superiority across workloads, an isolated dispatcher-only effect, improved answer quality, steady-state capacity, or migration payback. The resident treatment jointly changes placement, dispatch and recurring-control behavior. OFF has 128 physical experts; ON and resident have 160. The activation backend is all-gather/reduce-scatter; the results do not cover an untested sparse token-all-to-all serving path.

The LongBench ON session contains no ordinary asynchronous EPLB-launch log entries; NuminaMath contains three across its entire server lifetime, including warmup. These counts are neither measured-phase cycle counts nor committed migration counts. Ordinary native logs do not attest normal commit completion or committed-state consistency; HTTP drain is not a commit. Neither workload demonstrates long-horizon adaptation payback.

There is one group and one server episode per method per workload. No confidence intervals, significance tests, request bootstrap or pooled overall effect are reported. Execution order differs across workloads but is not replicated within either. The shortened LongBench generation retains its prior pilot-calibrated arrival rate, so neither a saturation comparison nor a capacity claim is warranted. Further equal-generated-work measurements would be needed to resolve the NuminaMath mechanism; none were added beyond the requested six sessions.
