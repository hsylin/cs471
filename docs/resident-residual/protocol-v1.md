# Residual resident-path cost: premeasurement protocol

This study diagnoses the remaining cost of the previously frozen fused resident dispatcher, then evaluates one selected deployable repair on fresh constructed inputs and fresh arrival rows. It does not change the earlier 83-file execution closure, protocol or outcomes. The final implementation is identified by a separately sealed selection manifest before fresh treatment timing. The diagnostic and final execution inventories are distinct and both must be archived.

## Question, prior evidence and scope

The preceding held-out study observed a high-load service ratio of 1.02709 for the fused static method relative to stock EPLB-off, while its primary mean-response ratio was 1.28528. Across main groups and loads, arithmetic mean service was 733.580 microseconds for stockoff and 753.829 microseconds for the fused method. The approximately 20.25-microsecond gap occurred throughout the episode, including ordinary positions and positions corresponding to the removed controller boundary. These observations motivate a diagnostic; they do not identify a causal component.

The earlier known-home adapter still executed a custom remapping kernel with 160-slot geometry. It was neither a selector-free path nor a runtime lower bound. The new diagnostic separates three narrower questions: the cost of the online selector invocation package, the effect of excess empty GEMM programs, and the cost of mapper input-validation checks. It does not claim to decompose all Python/framework overhead or to sum overlapping profiler durations into total runtime.

The hardware/model scope stays fixed: the reserved two-H100 pair, pinned Qwen3-30B-A3B layer 0, BF16, B128, top-8, eager execution, replicated input on two ranks, native expert kernels and native output reduction. Every measured forward computes the actual stock gate/top-k and float32 combining weights. There is no full-model generation, dynamic batching or token-all-to-all claim. Stockoff has 128 physical slots; the previous fused method and resident repairs retain the fixed 160-slot placement and a maximum allowance of 32 extra replicas. Equal allowance is not equal resident memory.

## Bounded development diagnostic

Use exactly four previously observed resident-fix pilot groups: two GSM8K-test and two WildChat groups. Each supplies the same 64 authenticated B128 batches, cycled eight times for 512 measured completed jobs. Reuse is explicit and these are not new independent requests. Two technical repetitions use exact reverse treatment order within each group, with the base orders declared before diagnostic timing. All seven variants occur in every group and repetition: 56 treatment executions. Pairwise precedence is balanced by reversal; exact position balance is not asserted and actual positions must be reported.

| Variant | Online physical selection | GEMM launch extent | Mapper input checks |
|---|---|---|---|
| Stockoff/full | Native logical placement | Native full | Native path |
| Stockoff/trim | Native logical placement | Proven-safe trimmed view | Native path |
| Previous fused/full | Unchanged one-launch greedy policy | Native full | Existing fused checks |
| Previous fused/trim | Unchanged one-launch greedy policy | Proven-safe trimmed view | Existing fused checks |
| Exact-ID replay/full | Precomputed identical physical IDs | Native full | Same fused-input checks |
| Exact-ID replay/trim | Precomputed identical physical IDs | Proven-safe trimmed view | Same fused-input checks |
| Exact-ID replay/full, checks removed | Precomputed identical physical IDs | Native full | Only these checks removed |

The exact-ID replay returns actual physical IDs authenticated against the online policy on identical logical inputs. It retains real stock gate/top-k, real combining weights, the same expert weights and native reduction. Known-ID construction is excluded; timed selection of the saved ID tensor/view and all subsequent work remain charged. It is an optimistic mechanism test, not an online competitor or a universal lower bound. Changes in ID-buffer reuse/address and cache behavior remain part of this intervention; it is not an exclusive GPU selector timer.

The trim intervention calls the native alignment implementation unchanged and exposes a shorter sorted-ID view to the subsequent GEMMs. It leaves native alignment work, full backing allocation and useful expert arithmetic unchanged. It charges every adapter cost, including source-compatible argument/metadata validation, Python dispatch and view construction, and changes downstream launch extent. It therefore identifies the effect of this launch-extent package, not the cost of alignment initialization/allocation. Both stockoff and the resident path receive the intervention in the diagnostic so that a generic backend improvement is not mislabeled as a resident-policy benefit.

A static 5,056-row bound, or 79 M tiles of 64 rows, is permitted only with the exact source proof: alignment excludes nonlocal routes before its padded count; there are at most 1,024 routes per job; stockoff has at most 64 local experts; and the unchanged greedy resident policy activates at most 64 copies per rank. Its active cap is at most `max(48,48,ceil(128/2)) = 64`. Consequently padded local rows are no greater than `1024 + 64*(64-1) = 5056`. The proof must cover both matmuls and supported valid inputs. Bound and output equality checks are required on actual and adversarial inputs. No `.item()`/host readback of the actual padding count may be added to the deployable timed path. An unproved bound stops this intervention; observed fast cases cannot justify truncation.

The seventh variant removes only the fused mapper's Python shape/layout/device/type validation, holding the replay hook, pointer selection, counters and downstream geometry fixed. It does not identify forward-context setup, FCFS coordination, ACK overhead or all host costs. No host-context hoisting is included.

For each group, first average its two technical repetitions. Report paired service differences in microseconds and paired service ratios, then equal-weight the four groups. Compute selector-package contrasts separately under full and trimmed geometry; compute full-minus-trim contrasts separately with online and replay selection; report their difference-in-differences. Report stockoff's own trim contrast and the check-only contrast. Do not add component costs as though interactions were zero. No confidence intervals, p-values or new performance acceptance gate are assigned to these reused-input diagnostics. Any separate profiler run is excluded from timing evidence and labeled accordingly.

## One implementation selection and development check

Select at most one deployable repair using the complete diagnostic matrix and verified source mechanism. Offline exact-ID replay is ineligible. Record the exact change, its bounded support, the diagnostic basis and source hashes in the selection manifest. Validate it against stockoff and the unchanged previous fused implementation on the same four reused groups, two reverse repetitions: 24 additional development executions. This is a check of one chosen implementation, not a parameter search. A failed correctness proof stops implementation progression; an unfavorable performance result is retained rather than retuned away. Any necessary apparatus correction must be explicitly amended and frozen before further measurements.

The completed 56-run diagnostic selected launch dispatch as the next bounded implementation target. Arithmetic service means were 726.946 microseconds for stockoff, 733.702 for stockoff plus trim, 744.478 for previous fused, 714.928 for checked exact-ID replay, 751.191 for previous fused plus trim, 724.834 for checked replay plus trim, and 715.143 for unchecked replay. The trim package increased service in this diagnostic; removing mapper checks showed no observed useful gain. These are equally weighted descriptive means over the four groups and two technical repetitions, with no significance claim. The replay contrast does not by itself separate GPU work from launch dispatch, buffer behavior or other selector-invocation costs. No claim that launch dispatch explains the entire residual is made before the selected implementation comparison.

The one selected candidate for the 24-run development check uses `selector='fused'`, `selector_launch='prebound_compiled'`, `alignment_trim=False`, and `mapper_input_checks=True`. It prebinds a compiled Triton launcher for the **same existing fused GPU kernel**, fixed shape, arguments and single-stream buffer contract. It preserves the previous algorithm, exact physical assignments, per-call input checks and native full alignment/GEMM extent. Both paths receive normal excluded preflight/compilation conditioning; the distinction is charged invocation of a prebound compiled launcher versus the previous warm JIT dispatch path. Archive the compiled kernel identities, invocation specializations and runtime launch metadata, and test actual output/assignment equality before using it on fresh treatment inputs. This candidate is justified as a mechanism to test, not an established speedup.

Diagnostic plan freeze-v2 is the plan actually executed for the 56 runs. The earlier freeze-v1 was an unexecuted draft; freeze-v3 was queued then cancelled before GPU execution. Preserve these statuses and the exact executed v2 source snapshot. Their version numbers must not be confused with the output-directory label. The selected implementation receives a separate execution freeze before its 24 development runs and fresh confirmation.

The 24-run development check also includes one separately labeled host-submission diagnostic on the first reused group only: 32 actual logical batches, two reverse arm orders, and the previous/selected mapper paths on each rank (128 mapper invocations per rank). Both paths are prewarmed. The timer surrounds the mapper call; CUDA inference-stream completion is awaited only after stopping that timer and before the next call. Archive the raw host-submission intervals, order, inputs, exact compiled-object/hash correspondence and correctness in `submission-diagnostic.json`. This measures the submission-call package, including any driver enqueue behavior, not exclusive GPU duration, full layer service or an additional inferential treatment trial. It adds no confidence interval, parameter search or change to the 24 service-execution count.

The final comparator named `previous` is the complete earlier fused static implementation, including its ordinary per-job mapper checks and native full launch extent. The comparator named `stockoff` is the actual supported upstream EPLB-disabled layer in the common harness. A control-specific diagnostic optimization must not silently replace either final comparator. If the selected change is generally applicable to stockoff too, its diagnostic evidence and this limitation must be reported.

## Prespecified final inference and decision

For positive metric `y`, compute paired log ratio `log(y_fix)-log(y_control)` within each group/type/load. Average the two arrival-type log ratios within content group, then groups within dataset, then the two dataset means equally; exponentiate. The primary endpoint is high-load (`rho=0.85`) **mean response** for fix/stockoff.

Resample the eight whole content bundles independently within each of the two dataset strata, retaining all types, loads, arms and endpoint pairings. Use 100,000 NumPy PCG64 draws with seed **471812**, dataset order `gsm8k_train`, `wildchat`, and linear quantiles. Save the SHA256 of concatenated complete `[100000,8]` draw arrays encoded little-endian int64 C-order. This conditional content-bundle uncertainty does not quantify fresh-day, hardware-allocation or production-request variation.

The primary useful-gain requirement is a two-sided 95% interval whose upper ratio bound is **strictly below 0.95**. The ten regression guards are, relative to each control (`stockoff`, `previous`): mean response for each dataset at each load (four), plus aggregate high-load p95 response (one). Every guard requires a one-sided **99.5%** upper ratio bound at most **1.02**, a Bonferroni family of ten at 0.05. The 5% and 2% margins are carried-forward engineering criteria, not numerical tolerances or values fitted to fresh outcomes.

Delete each actual final source calendar date jointly across services and recompute the high-load mean-response point ratio against both controls. Average remaining types within group and surviving groups within dataset, with the two datasets equally weighted. A missing dataset fails. Every date-deletion point must be at most 1.02; report all points/ranges, with no additional CI or new-day claim.

Only if the stockoff primary, all ten guards and all date checks pass is fix/previous high-load mean response tested as a hierarchical secondary endpoint, using the same two-sided 95% upper-bound-below-0.95 criterion. Otherwise it remains a descriptive point with no interval or confirmatory claim. Overall advance requires this eligible secondary to pass as well. An observed regression whose primary interval lies wholly above 1 must be reported as such, not merely as failure to reach 5%.

All 24 dataset/type/load/contrast cells, both load aggregates, service, queue, mean trial p95/p99, completed episode extent, drain and finite-episode throughput are descriptive outside these endpoints. Distinguish geometric paired ratios from arithmetic mean summaries; do not pool jobs into an artificial sample size. Pilot/calibration and development results have no final confidence intervals or performance gates. Keep all outcomes, including unfavorable diagnostics, guard failures and inconclusive results.
