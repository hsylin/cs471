The original LongBench pilot was not prefill dominated: its summed native request durations were about 2.85 seconds in prefill and 17.41 seconds in decode. Therefore the new LongBench generation budget deliberately targets short-output execution. Prompts are neither shortened nor reselected. This configuration does not measure full-length summarization quality, and “prefill bound” will not be inferred from the dataset name.

Each group runs native vLLM with EPLB off, native vLLM with EPLB on, and the unchanged fixed-resident method. All use the same complete pinned Qwen3-30B-A3B checkpoint, eight H100s on kh074/kh077, existing AgRs activation backend, and exact matching inputs and arrival calendars within a workload. The methods' expert budgets remain as previously defined: OFF has 128 physical experts, while ON and resident have 160. The resident code and correctness admission are unchanged.

There are six fresh servers, 96 measured HTTP requests, and 96 pilot warmup executions. LongBench order is resident → OFF → ON; NuminaMath order is OFF → ON → resident. Each server runs the same eight pilot prompts twice before its 16 final requests. Generation budgets apply equally to warmup and measurement within a workload. Every admitted request drains. Original per-workload pilot-calibrated arrival rates remain fixed; they are not retuned after shortening LongBench generation, so this is not a saturation or sustainable-capacity study.

The amended protocol binds the original source manifests, exact first-group identities, calendars, implementation and pilot admission. It preserves the original parent protocol and records the user's scope change. Neither selected final dataset was executed in the superseded WildChat-only partial run.

Report each workload separately: mean and p95 full response from scheduled arrival, first-token latency, completed elapsed including arrival horizon and drain, output lengths and hashes, cache/preemption counters, and native prefill/decode duration sums. The dominant request phase is whichever of prefill/decode has the larger summed duration, requiring exactly 16 completed observations for both. This phase classification is not proof that GPU kernels are compute- or bandwidth-bound. If the intended phase does not dominate, disclose that outcome without selecting a replacement group or changing its budget.

One group means descriptive results only. There is no confidence interval, significance test, or estimate of run-to-run variability. The previous four-group intervals are not reused. The 5% useful-gain and 2% regression margins remain descriptive point checks. A lower latency with fewer generated tokens is not automatically equal-work speedup; matching timing does not establish semantic quality. Native asynchronous commit completion remains unverified by ordinary logs, and successful HTTP drain is not evidence of committed EPLB weights.

Execution and reporting sources are versioned separately from the frozen experiment artifacts.
