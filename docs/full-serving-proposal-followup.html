Resident bottleneck fix and proposal B1–B4 follow-up

Status: all four full-model pilots passed admission; the final fourteen-session protocol is frozen. No final speedup measurements yet. This follow-up implements the user's two requests without replacing the earlier natural-EOS or equal-output results.

What the previous penalty does and does not show

On the previous matched-output NuminaMath episode, resident mean response was 50.41 ms (0.47%) above OFF. Summed native decode duration divided by sixteen requests was 52.02 ms higher; native prefill and queue durations were nearly unchanged. Thus decode is the relevant interval to investigate, but one group does not isolate the cause or prove that this small difference repeats.

LongBench has a different pattern. Resident mean response was 28.64 ms higher, while native mean RUNNING duration was 2.07 ms lower and native queue duration was almost unchanged. Approximately 30.7 ms of the difference lies outside that native execution interval. Those boundaries include frontend, transport, dispatch to engines and response handling; the records do not isolate one component. A faster GPU dispatcher should not be presented as an established fix for that separate gap.

Structural deduction: for identical logical routing, EPLB OFF already activates at most one physical copy of each expert. Our one-home dispatcher also uses one copy per expert, so it cannot reduce the global active-expert count relative to OFF; its opportunity is to redistribute that work across ranks. Relative to replica-spreading native ON, avoiding activation of multiple copies can offer a separate benefit. This explains why beating ON need not imply beating OFF, but does not quantify any particular measured gap.

The original full-model pilot completed and produced sixteen worker traces. On rank0, NCCL collective kernels account for70.76% of summed kernel duration in the long-input trace and49.86% in the decode trace; mapper kernels account for0.29% and1.42%. These profiled sums can overlap and include waiting. They show that collectives dominate the recorded GPU kernel-duration budget, not that network bandwidth is saturated or that those percentages are an end-to-end critical-path decomposition. The mapper is an avoidable extra cost relative to OFF, within a much larger shared execution cost.

One equivalent implementation improvement

The original one-home planner globally sorts up to32 shared experts and processes them serially. The fixed map connects four independent pairs of EP ranks. Decisions in one pair cannot affect another pair. The new planner sorts the eight shared experts within each pair and processes all four pairs together in eight serial iterations, retaining exactly the original load, active-copy cap and tie-breaking rules.

On one reserved H100,110 GPU/oracle cases passed across int32/int64 IDs,1–65,536 rows, skew, ties, padding and changed-input CUDA graph replays. Six technical GPU timing samples per condition showed lower mapper cost for every tested condition. At eight uniformly distributed rows, medians were3.43µs for the original and1.70µs for the new planner. These are synthetic routing kernel measurements, not authentic workload latency or an end-to-end speedup. Pilot full-model profiles and representative numerical checks are required before final execution.

The parallel-planner pilot has also completed and passed runtime admission. Its sixteen traces show lower mapper kernel duration per call in the sampled decode phase (rank0 fused mapper2.83→1.86µs). The two profiled executions contain different numbers and mixes of kernel calls, so comparing their summed times would not isolate implementation speedup. The unprofiled equal-output final comparison remains pending; no final performance gain is asserted.

Gate semantics and costs

The pinned CUDA deployment uses native asynchronous EPLB. B3/B4 hook the native async planner after its candidate is computed and before transfer. For rejected layers, the hook returns the current map, preserving native unchanged-slot transport and ordinary commit bookkeeping. It does not race the worker's rebalanced flag, replace the planner, move weights independently, or call draining a commit. This conservative implementation removes rejected weight movement but still pays native no-op per-layer bookkeeping.

Both gates collect the same logical-demand history. At each engine step, before native completion can change the mapping, physical assignment counts are converted through the then-current physical-to-logical map into a2,000-step logical ring. Dummy steps contribute zero counts and still advance the shared clock. The two1,000-step windows immediately precede the decision. Snapshots are reduced across ranks; all eight ranks compare the clock and digest of history, current map, native candidate and admitted map before any transfer. This avoids incorrectly reinterpreting old physical counts using a newer map. The native candidate itself is preserved as native output and recorded separately.

The initial settings are prespecified rather than claimed optimal: native1,000-step windows and3,000-step proposal cadence,5% predicted peak-load improvement, and total variation at most5%. B3 requires a complete nonzero recent window; B4 also requires a complete nonzero previous window and the stability threshold. Equal sharing among replicas remains an approximation, not measured runtime payback. Incomplete history, zero demand, unchanged maps and rejected proposals are explicit outcomes. Both gates pay continuous history collection, reduction, decision, agreement and logging overhead. Native B1/B2 remain uninstrumented references.

Per-rank public records include raw logical counts, old/candidate/admitted mappings, TV, predicted gain, decisions, transferred tensor bytes, native commit enqueue and observed CUDA-event completion. An event is recorded after native weight-copy and map-copy enqueue, then queried on subsequent engine steps. Completion not observed by the final step remains censored. This is stronger than treating async drain as commit, but it is not a full hash of migrated model weights or an all-logit equivalence proof.

Completed pilot evidence: both gated arms exercised two proposal cycles across all eight ranks. The first cycle lacked a complete recent window. On the second cycle B3 admitted all48 layers, while B4 rejected all48 as unstable. B3 recorded60,652,781,568 received expert-tensor bytes across ranks; B4 recorded zero. All768 rank/layer commit events per arm were observed complete, including native no-op commits. These are pilot feasibility and branch-coverage observations, not final speed or quality results. All309 remote pilot files matched local bytes and each controller source manifest matched its Git revision.
