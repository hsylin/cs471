# Development explanation and residual limits

The development experiments identify avoidable overhead in the current method's execution path. They do not establish that resident-copy selection outperforms stock EPLB-off. The current method continues to observe routes and invoke a forced-SKIP controller even though its placement never changes. It also executes three kernels to count logical routes, choose resident homes, and map/record physical IDs. Stock EPLB-off uses 128 resident slots and does not run that physical replica-selection path.

The matched 60-trial factorial diagnostic held the 160-slot placement, logical inputs, combining weights and physical-assignment policy fixed. Removing the observation/controller package reduced mean service by 52.41 microseconds per job with online selection and 51.34 microseconds with known homes. Replacing online selection with precomputed identical homes reduced service by 35.69 microseconds with the current controller and 34.62 microseconds with control inactive. The factorial average effects were 51.87 and 35.15 microseconds, with a 1.07-microsecond interaction. These are whole coordinator-service differences for two implementation packages. They do not isolate CPU planning, individual launches, synchronization, memory bandwidth or expert arithmetic. The known-home arm retains a mapping adapter and uses prior knowledge; it is a diagnostic estimate of removable work, not a runtime lower bound or deployable comparator.

The selected repair makes placement explicitly static, removes per-job observation/planning work, and combines the same current-batch home policy into one GPU launch. It also reuses output storage on the single sequential inference stream. In a separate 36-trial development run, all current/fix physical assignments matched the independent integer oracle. Averaging the two technical repetitions within each of six groups, the geometric service ratio was 0.892074 versus the current method; completed-elapsed ratio was 0.895295. This matched comparison supports improvement of the existing custom method. It changes the controller package and selector implementation together, so it is not a clean isolated fusion ablation. Comparisons with the previous three-kernel run require cross-run normalization: ratios were 0.942603 using stock-off as anchor and 0.953048 using current as anchor. Neither adjustment removes possible run/order/thermal effects.

The repair still lost to stock EPLB-off in every development group. Its group-paired service ratio was 1.021542, ranging from 1.007921 to 1.036421; completed-elapsed ratio was 1.021148. It therefore enters fresh confirmation as the best bounded custom repair tested, not as an established improvement over stock. No development confidence interval, significance test or adaptive performance gate is assigned. The fresh primary criterion, regression guards and descriptive MBPP sentinel remain unchanged.

The residual comparison contains differences beyond selector overhead. The custom method retains 160 physical slots, versus 128 with genuine stock EPLB-off, and keeps EPLB construction/layout buffers allocated while inactive. It preserves stock gate/top-k, expert kernels and native output reduction, but changes physical placement and dispatch. The single fused selector still has nonzero work; less rank imbalance alone need not repay it. Development results cannot isolate the remaining difference into kernel efficiency, host overhead, allocation, cache or memory-bandwidth components. We should not call the custom static mode stock EPLB-disabled, nor turn a smaller token/active-copy count into a runtime optimality claim.
