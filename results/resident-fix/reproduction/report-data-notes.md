## Suggested methods text

We evaluated a custom static-residency repair in one pinned Qwen3-30B-A3B MoE layer (layer 0; hidden width 2,048, expert intermediate width 768, 128 logical experts, top-8 routing), using BF16 and two reserved H100 GPUs. The comparison used vLLM commit `db9527a46873454610df6dbedf79a36d6bf1a7f6` and checkpoint revision `ad44e777bcd18fa416d9da3bd8f70d33ebb85d39`. Every timed forward recomputed the actual stock gate, logical top-k and combining weights and executed the native Triton experts and native output all-reduce. Inputs were replicated across the two ranks. This was an eager, fixed-B128 layer experiment, with neither token all-to-all nor full-model request generation.

The stockoff comparator used upstream EPLB-disabled behavior in the controlled harness, with 128 physical expert slots (64 per rank). The unchanged current method and the repair used 160 slots (80 per rank), including the same 32 additional replicas and exact fixed placement. Thus the experiment imposed a common maximum replica allowance, not equal resident memory. The repair retained the current method's physical-assignment policy while fusing its selector into one kernel and disabling the recording, planning and migration subsystem for fixed residency. It remained a custom enabled-layout/static-residency mode, not a supported upstream EPLB-off configuration. The implementation was selected using reused development inputs before fresh treatment timing.

Fresh content comprised 704 source documents: 320 GSM8K questions, 320 WildChat first-user turns and 64 MBPP task descriptions. Each dataset was split into groups of 32 documents. GSM8K and WildChat supplied two pilot and eight final groups each; MBPP supplied one pilot and one final group. The smaller MBPP allocation was fixed before new timing because only 73 eligible tasks remained after exclusions. MBPP was retained as a descriptive operational sentinel and excluded from main bootstrap inference. Source selection excluded all 2,695 previously selected document identities and 56 older captured source documents, with normalized exact and five-shingle Jaccard duplicate checks on full text and model-visible prefixes. The freshness claim is relative to this project's declared exclusion inventory, not to model pretraining or all possible semantic overlap.

Each document was processed independently through the pinned BF16 embedding, causal layer-0 attention, normalization and router, retaining at most its first 512 tokens without a chat template, special tokens, answers or generated continuations. The audited banks contain 62,931 authenticated source-position records. Only the exact captured hidden vectors enter measured execution; captured HuggingFace expert IDs and rounded combining weights are provenance and are not injected into vLLM routing. For each group, seed 471703 constructs 4,112 distinct unordered B128 record combinations: 16 conditioning-input combinations and 4,096 measured jobs. Records are distinct within a job but recur across jobs. These constructed jobs are not natural independent requests. Bank materialization, host-to-device transfer, reference computation and conditioning occur outside treatment timing; timed work includes access to the prepared job, routing, expert computation, normal control work for the current arm, coordinator communication and completion acknowledgements.

The 44 assigned arrival intervals contain 180,224 release rows and 44 following boundary rows, selected from the original Azure code and conversation CSVs. They exclude all 140 earlier intervals, including boundaries. Each group receives one interval per service, shared across both offered loads and all arms. Baseline-only stockoff calibration defines capacities before immutable calendar scaling to offered loads 0.5 and 0.85. The frozen final design contains 192 main treatment trials (16 groups × two services × two loads × three arms) and 12 MBPP trials. The resampling unit is a whole main content group, retaining its paired services, loads and arms. The following qualifications should survive report compression:

- **Uniqueness:** “distinct job combinations” does not mean fresh captured records in every job, unique vocabulary tokens, or independently sampled requests. Every treatment trial has 524,288 measured record occurrences, drawn from its bounded bank. MBPP reuse is especially high.
- **Warmup:** the loader creates 16 conditioning-input combinations, while each trial executes 64 untimed conditioning forwards by cycling those 16 inputs, then resets state. Avoid saying there are only 16 warmup forward executions.
- **Arrival holdout:** first two dates per service supply pilot intervals and last five supply final intervals. The service-specific date splits overlap in calendar date. Date-deletion checks link shared actual dates but do not estimate performance on new days.
- **Timing:** response ends at inference-stream output completion and the common ACK. Completed episode extent includes the horizon and normal completion tail. Host-side waiting, FCFS bookkeeping and communication belong to this harness; response, service, throughput and GPU occupancy are not interchangeable quantities. Preloading is excluded, so this is not an end-to-end ingestion benchmark.
- **Numerical coverage:** the frozen design compares current/fix outputs with stockoff on all 4,112 prepared batches per group, uses 64 selected token positions for FP32 reference checks, and samples 16 whole postflight batches per trial. Tolerances are `atol=0.02, rtol=0.03`; their joint test is not a universal absolute-error ceiling. Capture-audit PASS authenticates artifacts and recorded boundary/router checks, not completed final runtime validation or downstream answer quality.
- **Implementation scope:** the fused repair requires B128/top-8, the exact frozen 160-slot map, and sequential buffer consumption on one constructing CUDA inference stream. It does not support arbitrary placement changes, concurrent/multistream reuse or additional model/backend/hardware claims. The repair is not a new routing-policy comparison because it preserves the current policy's physical assignments.
- **Interpretation:** stockoff uses fewer resident slots. A fix/current gain alone does not establish a gain over stockoff. The frozen primary, ten guards, linked-date point checks, hierarchical secondary and separate MBPP sentinel must be reported without replacing them with a favorable subgroup. The 5% and 2% margins are engineering criteria, not numerical tolerances or literature-established constants.
- **Resource reporting:** peak process memory includes all instantiated comparator layers, prepared inputs and references; it is not a standalone engine memory measurement. The shared maximum replica budget does not remove this limitation.
- **Audit independence:** the source/row and capture audits are separately implemented by the same team using the same artifacts. They are not external-laboratory reproduction or an independent GPU recapture.
