# FP32 reference precision audit

No frozen execution change is indicated. A CPU-only probe in the exact installed `torch2.13.0+cu129` environment reported `get_float32_matmul_precision() == "highest"` and `torch.backends.cuda.matmul.allow_tf32 == False` before and after importing vLLM, its config, Qwen3 MoE module and EPLB state. CUDA remained uninitialized throughout. Both targeted TF32 override environment variables were unset in that probe. The newer `fp32_precision` property reported `"none"`; it was not explicitly configured by this harness.

The installed PyTorch `Context.h:496–499` selects HIGHEST unless `TORCH_ALLOW_TF32_CUBLAS_OVERRIDE` enables HIGH. Its `set_float32_matmul_precision` documentation states that highest uses FP32 internal computation. Installed source SHA256 values and observed flags are preserved in `stock-fp32-defaults-evidence/audit.json`.

A full installed-vLLM search found only two relevant global-setting paths. [`gpu_worker.Worker.__init__`](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/v1/worker/gpu_worker.py#L182-L201) sets the worker precision from an environment option whose [default is highest](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/envs.py#L621-L629). Our standalone facade does not instantiate that Worker. The optional [batch-invariance initialization](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/determinism/batch_invariant.py#L1166-L1176) explicitly chooses IEEE. All three installed files exactly matched the pinned public sources. Other search hits were explicit per-kernel Triton precision arguments, not switches of PyTorch's global reference-matmul setting. The facade, reference helper and launch scripts contain no enabling switch.

The completed GPU runs did not archive their actual global precision flags. This CPU-only probe did not execute GPU-specific constructors, reproduce the allocation's inherited environment, or inspect GPU arithmetic instructions. The defensible label is **dense FP32-tensor reference, with highest/TF32-disabled defaults verified in the installed environment and through the tested imports**. Do not turn that into a direct per-run IEEE-execution attestation. The separate capture process's explicit TF32 setting does not persist into these workers.
