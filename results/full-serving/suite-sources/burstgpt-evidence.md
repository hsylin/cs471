# BurstGPT arrival provenance

BurstGPT provides production-derived request timing and token-length metadata, not the corresponding prompts. Its KDD2025 paper distinguishes real arrivals from separately sampled dialogue content; the accessible preprint's methods allow timestamp scaling and let the tested model determine output length. Pairing our text with these timestamps is therefore a labelled hybrid workload, not recovery of the original GPT requests. [Wang et al. 2025](https://doi.org/10.1145/3711896.3737413) · [Accessible preprint methods, §§4.1–4.3](https://arxiv.org/html/2401.17644v4#S4)

We acquired failure-inclusive `BurstGPT_1.csv` from release v2.0, asset 341026710, matching its published SHA256. The pinned repository licenses it CC-BY 4.0. The six actual CSV columns include timestamps, model/service labels and token counts; they do not include the newer session/elapsed-time fields advertised by current main. [Pinned release](https://github.com/HPMLL/BurstGPT/releases/tag/v2.0) · [Pinned license](https://github.com/HPMLL/BurstGPT/blob/7eb2c4f8350f8a6985272386f5c14af1f678b299/LICENSE)

The diagnostic selects contiguous rows 804589–804612 by a fixed seed before timing any method. It retains all 24 rows, original timestamp ties and source failure indicators; this selected block happens to contain zero zero-response records. Its original span is 19 seconds and declared horizon 20 seconds. Source token counts remain metadata and do not set Qwen prompt or output lengths.
