修正相對原始 B4 的平均回應時間減少 0.90%（LongBench）與 2.21%（NuminaMath），均未達預先設定的 5% 有用增益。修正相對 OFF 仍慢 4.60% 與 5.61%，均超過 2% 退步門檻。因此，本次結果不支持把此修正視為達標的端到端優化。

修正只省略已經由八個 rank 一致確認、與舊映射完全相同的 inverse-map commit。原生 planner、worker、傳輸、readiness、pending reset 與 consumed-event retirement 都保留。先通過正確性與診斷審閱，再凍結來源及協定，最後才進行這六組測量；未依最終結果選最快版本或重調政策。

正確性、失敗紀錄與解讀界線

  • 修正的既有 admission 已驗證八 rank metadata、CUDA graph readers 與 48 層 full weights；最終測量關閉昂貴 shadows。最終 commit audit 不等於再次驗證全模型權重或品質。
  • 原 noop admission 的初次 CPU audit 錯把合法的下一層預取視為異常；修正分析後通過，原失敗保留，沒有重跑 GPU。
  • host-pair-v1、controls-admission-v1、shapes-run-v1 的 GPU 前失敗保留。舊 shape 診斷缺少持續對齊證據，另以原生 DP ordinal 診斷補足；沒有重跑健康實驗。
  • 同一組八張 H100：Qwen3-30B-A3B BF16，EP8／DP8／TP1，native all-gather/reduce-scatter。B4 有 32 replicas，OFF 沒有額外 replicas，因此對 OFF 的比較包含配置差異。
  • 固定 prompts、到達 calendars、rates 與輸出長度；每次 HTTP force-close，POST 不重試。每組使用全新服務程序。LongBench 順序 OFF→B4→修正；NuminaMath 反向。
  • 單組描述性結果；不保證 tokens、routes、batching、KV、quality 相同，也不提供統計顯著性。沒有將 host sums、NCCL duration 或 drain 推成節省時間、bandwidth 或 commit 證明。
  • 選擇依據是精確冗餘與正確性；詳細 profiling 未作為這個有限修正的比較前提。關鍵路徑歸因未完成，不能用這份報告宣稱已找到主要瓶頸。
  • 原始紀錄、prompts、outputs、token arrays、logs、profiles 皆未公開。公開彙總只能重算表格與比值；從原始請求完整重建須另有私有資料授權。
